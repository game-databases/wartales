### 2.1 Recount protocol (r1)

Law: **every count this spec consumes is re-derived from the tree at build
time and asserted, never hardcoded.** The probes are evidence commands, not
new gates — a probe failing means the owning stage's gate failed first, and
F2 acceptance must not run over a tree mid-regeneration. Measured during the
r1 fix round: the locale plane was deleted and rewritten UNDER this revision
(one 14,246-row transient, then an absent-file window, then the settled
14,456-row state) — the concrete failure mode this protocol exists for.

```sh
PYTHONIOENCODING=utf-8 python - <<'PY'
# R-1 canonical census shape (owner: census-closure)
import json, pathlib, sys
sys.path.insert(0, "pipeline/tools"); import wave_kinds
total = 0
for k in sorted(wave_kinds.MANAGED_KINDS):
    n = len(pathlib.Path("extracted/data", k + ".jsonl").read_text(encoding="utf-8").splitlines()) - 1
    assert n > 0, k                      # every managed kind has rows
    total += n
consts = len(pathlib.Path("extracted/logic/constants.jsonl").read_text(encoding="utf-8").splitlines())
assert consts >= 2                     # 1 meta line + >=1 row
print("R-1 ok:", total, "canonical rows +", consts, "constant lines")

# R-2 availability shape (owner: availability-regenerated)
import collections
LOCS = ["en","fr","de","es","pl","pt-BR","ru","ko","zh"]   # frozen client codes (spec.md)
rows = [json.loads(l) for l in pathlib.Path("extracted/relinks/locale_availability.jsonl").read_text(encoding="utf-8").splitlines() if l.strip()]
assert rows, "locale_availability.jsonl missing/empty - regen in flight"
by_kind = collections.Counter(r["kind"] for r in rows)
hist = collections.Counter(len(r["availableLocales"]) for r in rows)
assert set(hist) <= {0, 8, 9}, hist                       # trimodal law
for r in rows:
    if len(r["availableLocales"]) == 8:                   # the 8-case lacks exactly fr
        assert set(LOCS) - set(r["availableLocales"]) == {"fr"}, r
filler = sum(1 for r in rows if "en" in (r["fields"] or {})
             for loc in LOCS if loc != "en" and loc not in r["fields"])
assert filler == 0, filler                                # omit-until-translated bites whole entities only
missing = sorted(set(wave_kinds.MANAGED_KINDS) - set(by_kind))
for k in missing:                                         # absence is STRUCTURAL, not a dig gap:
    meta = json.loads(pathlib.Path("extracted/data", k + ".jsonl").read_text(encoding="utf-8").splitlines()[0])["_meta"]
    assert not any(c.get("kind") == "localizable" for c in meta.get("columns", [])), k
print("R-2 ok:", len(rows), "rows /", len(by_kind), "kinds;", len(missing), "managed kinds structurally text-free")

# R-3 overlay inventory (owner: availability-regenerated)
pairs = {(p.parent.name, p.stem) for p in pathlib.Path("extracted/locales").glob("*/*.json")
         if p.parent.name in LOCS}
per_loc = {loc: {k for l, k in pairs if l == loc} for loc in LOCS}
assert len({frozenset(v) for v in per_loc.values()}) == 1, "asymmetric overlay plane"
print("R-3 ok:", len(pairs), "overlay pairs")

# R-5 relink header parity (owner: catalog-parity reads the sha; F2 reads the header fields)
head = pathlib.Path("extracted/RELATIONS.md").read_text(encoding="utf-8")[:2000]
for field in ("totals:", "directions:", "textKey coverage:"):
    assert field in head, field
print("R-5 ok: RELATIONS.md header carries totals/directions/textKey coverage")
```

Known asymmetries, preserved deliberately (do not "fix" either side; the
emitter converts once at the boundary):

- Canonical `_meta.buildId` is a STRING (`"20318128"`); registry/published
  map plane uses the INTEGER `20318128`.
- (r1) The build-id CARRIER NAME splits by plane: API documents the spec
  emits fresh (lists, entities, tooltips, db.json) carry camelCase
  `buildId` ([§11](#11-provenance-field-law-two-classes-one-whitelist));

  verifies it byte-for-byte against that projection. Exactly ONE spelling

## 3. Planes and ownership boundaries

Three artifact families meet at F2; the contract names each plane's owner
so no later piece edits across the line:

1. **Canonical repo plane** (stages 4–6 own bytes; F2 reads only):
   `extracted/data/<kind>.jsonl` (+ `_meta` line 1 —
   [spec-stages-datasets §3.2](spec-stages-datasets.mdx#32-canonical-layout--_meta-line-schema-unchanged-from-drafts)),
   `extracted/relinks/*`, `extracted/locales/*`,
   `extracted/relinks/locale_availability.jsonl`,
   `extracted/data/maps.json`.
2. **Contract plane** (F2 owns): JSON Schema draft-07 documents +
   one machine manifest under `contracts/` ([§14](#14-files-touched)).
   Schemas assert STRUCTURE (shape, types, enums, patterns) —
   never row counts, cell fidelity, or edge validity, which remain
   cdb_verify/validate_all territory.
3. **Published data plane** (stage 7 will own bytes; F2 pins shapes):
   the static, unauthenticated, CORS-open `/data/**` + `/cdn/**` trees
   served beside the site — the machine half of
   [seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page)
   and the satellite obligation of
   [FRAMEWORK §2.17](../../FRAMEWORK.md#217-overlay-satellite-per-project-option-overwolf-default).
   One data plane, two renders: the API never disagrees with the page.

Three contract-plane documents model REPO-plane artifacts on purpose so F2
acceptance is provable before any emitter exists: `overlay.schema.json`
(today's `extracted/locales/**`), `availability.schema.json` (today's
`locale_availability.jsonl` rows), and the committed registry schema
`maps.schema.json`. Repo-plane documents may carry repo vocabulary;
published-side documents may not ([§11](#11-provenance-field-law-two-classes-one-whitelist)
draws the line per DOCUMENT CLASS, and
[AC5](#ac5-provenance-whitelist-is-structural) enforces it per class —
the committed registry schema legitimately names `source`, `provenance`,
`publicationPlane`, because the registry owns those fields).

## 4. Stable identity and the kind universe

- **Entity id** = the canonical dataset `id`, VERBATIM (case-preserving,
  never slugified) — the immutable join key of
  [localization-architecture §5](../../_foundation/localization-architecture.md#5-data-layer-obligations--what-every-pack-must-ship)
  item 1. (r1) Observed id charsets, MEASURED across every row of all 40
  kinds (R-4 re-derives at build time): native ids are ASCII
  `[A-Za-z0-9_]+`; the corpus-wide union adds the hyphen through exactly
  two SYNTHETIC families (below), giving the universal pattern
  `[A-Za-z0-9_-]+`. Both patterns are frozen in
  `common.schema.json#$defs` (`entityId` native, `entityIdAny` universal);
  URL segments and pointer patterns derive from them
  ([§5.1](#51-files), [§9](#9-map-marker-payload-shape-for-mapsjson-marks),
  [§10](#10-icon-cdn-references)). A prettier display slug MAY be added
  later as an extra field/redirect source; it never replaces the id, and
  any rename ships a 301 map
  ([seo-standard §1](../../_foundation/seo-standard.md#1-url--information-architecture)).
- **Synthetic-id caveat**: `frescos`, `env`, `recipe` (sheet `craft`) have
  no native id column — their ids are pinned by `_meta.keyRule`
  ([spec-stages-datasets §3.2](spec-stages-datasets.mdx#32-canonical-layout--_meta-line-schema-unchanged-from-drafts)).
  (r1) Measured family patterns: `env` = `^env-[0-9]{4}$` (87/87 rows,
  `env-0000`…`env-0086`), `recipe` = `^recipe-[0-9]{4}$` (667/667 rows,
  `recipe-0000`…`recipe-0666`) — zero-padded row ordinals, HYPHENATED;
  `frescos` = the row's unique `place` ref (`A1Ruins`…), conforming to the
  native charset. These are stable WITHIN a buildid; cross-build diffing
  keys them on content, not ordinal (E3 versioned-truth work, R5/R10 digs).
  Published payloads carry them unchanged; consumers must not treat them as
  game-native. Any route/pointer/pattern that validates ids MUST accept the
  hyphen families — a pattern that rejects `recipe-0000` rejects 667 real
  recipes.
- **Kind universe of record** = the 40 managed kinds (importable, never
  retyped): `activity amb attribute battle bonus class condition confessions
  counter credits effect env fiefAdministration fiefAlignment fiefCondition
  fiefEvent fiefGoal fiefLaw fiefMission fiefPlace fiefPopulation frescos
  groupType icon input item itemType kingdom loot mission notify recipe
  region skill sound startChoice status trait tutorial unitPattern`.
- **Deferred kinds get no published endpoints in wave 1**: the
  HBSON-decoded corpora (`place`, `group`, `element`, `levelProps` →
  location-place / enemy group / npc-dialogue / poi-battle-scene), Steam
  `achievement`, `constant`, and subset views
  ([RELATIONS.md §Deferred kinds](../extracted/RELATIONS.md#deferred-kinds-not-promoted-by-stages-46)).
  Their schemas land with their promotion (wave 3), extending — never
  reshaping — the contracts here. Marker rows MAY already point at deferred
  kind names ([§9](#9-map-marker-payload-shape-for-mapsjson-marks)); such
  links resolve when promotion lands and stay honestly dangling before.
  (r1) Their TEXT already rides the locale plane: `place`/`group`/
  `element` availability rows and overlays exist today (R-2/R-3), so the
  overlay/availability contracts are kind-generic over managed ∪
  {`place`, `group`, `element`} NOW.
- (r1) **Locale segments are TWO planes with ONE bridge** (conforms to
  [spec-f4-app-shell.mdx §2](spec-f4-app-shell.mdx#2-locale-model--one-table-one-derivation)'s
  recorded r1 decision; see [§r1 conflicts](#r1-conflicts)):
  - DATA plane (file names, `/data/**` segments, payload locale values):
    CLIENT CODES verbatim — `de es fr ko pl pt-BR ru zh`; pivot `en` bare.
  - PAGE plane (URL prefix segments): PRESENTATION IDS per F4 §2 —
    lowercase, `pt-br` — paired 1:1 with the client codes; pivot `en`
    never appears as a segment ([DR-2026-08-20-locale-urls]).
  - BCP-47 presentation mapping (`zh`→`zh-Hans`, hreflang/`<html lang>`)
    is a PT16 rendering concern and enters neither plane; `locales.ts` is
    the single id↔client-code bridge between the planes.

## 5. Per-kind JSON schema contract (base + locale overlay)

Split per [FRAMEWORK §2.2](../../FRAMEWORK.md#22-entity--base--locale-overlay):
the base record is locale-FREE structure; prose lives only in per-locale
text fields; a locale file never mixes languages
([localization-architecture §1](../../_foundation/localization-architecture.md#1-architecture-one-dedicated-page-per-entity-per-language)).

### 5.1 Files

- `contracts/common.schema.json` — shared `$defs`: `provenanceEnvelope`
  (`buildId` integer + `coverage` object — the ONLY provenance carriers on
  API documents, [§11](#11-provenance-field-law-two-classes-one-whitelist)),
  `provenanceEnvelopeRegistry` (registry-native `buildid` integer +
  `coverage` — the served map projection variant, [§2.1](#21-recount-protocol-r1)),
  `coverage` variants (entity/index/map), `cdnIconPath`
  ([§10](#10-icon-cdn-references)), `entityPointer` (`{kind,id}` with `id`
  = `entityIdAny` — hyphen-bearing synthetic ids legal),
  `worldCoord`, locale-code enum (client codes), `entityId`
  (`^[A-Za-z0-9_]+$`) and `entityIdAny` (`^[A-Za-z0-9_-]+$`) id patterns
  with the two synthetic family refinements documented at
  [§4](#4-stable-identity-and-the-kind-universe).
- `contracts/kinds/<kind>.schema.json` ×40 — one per managed kind, each
  carrying three `$defs`:
  - `canonicalRow` — the canonical dataset row AS IT EXISTS TODAY
    (structure only; typed through the [§5.2](#52-cell-type-mapping-canonical--published)
    table). Exists so acceptance is provable against the live corpus before
    any emitter exists. This def models a REPO-plane row and MAY carry repo
    vocabulary (`textKey` bridges) — it is exempt from the published-side
    bans of [§11](#11-provenance-field-law-two-classes-one-whitelist),
    which [AC5](#ac5-provenance-whitelist-is-structural) scopes to
    `baseRecord`/`listEntry` accordingly.
  - `baseRecord` — the published record: `allOf` →
    `common.schema.json#/$defs/provenanceEnvelope`, plus `id` (matching
    the kind's id pattern: native, or the family pattern for
    `env`/`recipe`) and every non-localizable column verbatim, enums
    RESOLVED to case-name strings, icon descriptor replaced by the CDN
    path. Optional localized text fields (`name`, `description`, other
    localizable columns as strings) are legal HERE and present only in
    locale files — one def serves the pivot base file and the per-locale
    resolved view. No `textKey` objects, no `_meta` internals, closed
    `additionalProperties`.
  - `listEntry` — the row projection consumed by kind list indexes
    ([§7](#7-list-index-shapes)).
- `contracts/overlay.schema.json` — pins TODAY'S repo-plane overlay
  artifacts: an object keyed by entity id, values
  `{name?, description?, <otherLocalizableColumn>?}`, all-string values.
  Pins the `desc`→`description` alias and the omit-until-translated omission
  rule ([locale-key-convention §2, §6](locale-key-convention.mdx#6-filler-policy-application)).
  Kind-generic; (r1) instances span every kind with ≥1 availability row —
  managed kinds AND the deferred corpora, whose localizable columns differ
  (e.g. `world.name` on places); dig waves extend instances, never this
  shape.
- `contracts/availability.schema.json` — pins TODAY'S availability row:
  `{kind, id, availableLocales[], namedLocales[], fields:{<locale>:{...}}}`
  ([locale-key-convention §3](locale-key-convention.mdx#3-emitted-artifacts)).
  Shape only; the row-count/locale-set law stays in
  `availability-regenerated`. (r1) `kind` is NOT a closed enum of the
  managed 40: the plane legitimately carries the deferred HBSON corpora
  (`place group element` at r1). Membership is asserted, not enumerated:
  [AC4](#ac4-overlay-and-availability-shapes-match-the-emitted-artifacts)
  requires observed kinds ⊆ managed ∪ the reserved promoted-later names.

## 6. Static JSON API URL architecture

The load-bearing rule of
[seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page):
an agent can act on this database iff it can fetch an entity's JSON at a
STABLE URL DERIVED FROM ITS PAGE URL and get the same facts the page renders.

**(r1) Derivation rule (bijective, mechanical, two-segment-set):** take the
page path; strip the optional leading PAGE-plane presentation id; map it to
its paired DATA-plane client code (F4 §2 table, one bridge); prepend
`data/`; append `.json`.

| surface | pivot page (EN, bare) | locale page (presentation id) | data URL (client code) |
|---|---|---|---|
| kind list | `/{kind}` | `/{P}/{kind}` | `/data/{kind}.json` · `/data/{C}/{kind}.json` |
| entity | `/{kind}/{id}` | `/{P}/{kind}/{id}` | `/data/{kind}/{id}.json` (base) · `/data/{C}/{kind}/{id}.json` (base + that locale's resolved text; filler policy applied by omission) |
| tooltip sub-route | `/{kind}/{id}/tooltip` | `/{P}/{kind}/{id}/tooltip` | `/data/{kind}/{id}/tooltip.json` · `/data/{C}/{kind}/{id}/tooltip.json` |
| DB landing + taxonomy | `/db` (PT02) | `/{P}/db` | `/data/db.json` (locale-free tree; labels resolve from overlays/chrome) |
| map registry | `/map` (PT05) | `/{P}/map` | `/data/map.json` (published PROJECTION of the registry — [§9](#9-map-marker-payload-shape-for-mapsjson-marks)) |

with `{P}` ranging over the presentation ids (`de es fr ko pl pt-br ru zh`)
and `{C}` over the paired client codes (`de es fr ko pl pt-BR ru zh`). The
case-divergent pair is load-bearing: page `/pt-br/item/Gold` derives
`/data/pt-BR/item/Gold.json` — never `/data/pt-br/…`
([AC7](#ac7-url-namespace-disjointness-and-derivation-bijection) asserts the
divergent pair explicitly).

- Page-tree shape is pinned WITHOUT a `/db` prefix on entity routes (shorter
  canonical, kind-first hierarchy per
  [seo-standard §1](../../_foundation/seo-standard.md#1-url--information-architecture);
  FRAMEWORK's `/db/…` tooltip example is evidence shape, not doctrine —
  nw-site-new is reference, with listed deviations). One entity, one URL,
  forever ([FRAMEWORK §2.7](../../FRAMEWORK.md#27-url-architecture-is-the-product));
  adopting a prefix later is a rename with a 301 map, paid once.
- An entity unavailable in locale L (absent from `availableLocales`, per the
  trimodal availability law) has no L page AND no L data file — a true 404,
  never pivot prose ([filler policy](locale-key-convention.mdx#6-filler-policy-application)).
- **Site root composition**: paths here are root-relative. Today
  (localhost / standalone) the root is `/`; under the provisional umbrella
  placement it is `{hub}/games/wartales` — segments unchanged either way;
  domain placement stays owner-gated (Q1, [DR-2026-08-24-wartales-roster]).
- **Namespace disjointness (gated)**: the kind set, the reserved FIRST
  segments `{data, cdn, db, map}`, and the reserved TERMINAL segment
  `tooltip` are pairwise disjoint, and EACH locale segment plane (page
  presentation ids; data client codes) is disjoint from all three — asserted
  mechanically in
  [AC7](#ac7-url-namespace-disjointness-and-derivation-bijection). (r1)
  The two locale planes OVERLAP BY DESIGN — they are per-locale pairs
  (`pt-br`↔`pt-BR`; identical spellings for the other seven) — so AC7
  asserts their PAIRING (same length, lowercase-normalized correspondence,
  pivot-free) instead of disjointness between them. `tooltip` is reserved as
  a terminal segment because the tooltip sub-route occupies
  `/{kind}/{id}/tooltip`; the manifest carries BOTH reservation classes
  (`reservedPrefixes`, `reservedSuffixes`).
- No querystring locales; no pagination parameters on list indexes (each
  kind's index is one static file; largest is item — a
  tens-of-kilobytes artifact). The page-size-50 ruling
  ([DR-2026-08-18-page-size]) governs rendered listing pages, not data
  artifacts.
- `contracts/api.manifest.json` — the machine-readable form of this
  section (r1 shape): `{version:1, locales:{pivot:"en", pagePrefixes:[…8…],
  dataCodes:[…8…]}, reservedPrefixes:[…], reservedSuffixes:["tooltip"],
  kinds:[…40…], surfaces:{list, entity, tooltip, taxonomy, map},
  localeCoverage:{mode:"emitted", kinds:[…recount…]}, derivationRule:"…"}`.
  `pagePrefixes`/`dataCodes` are positionally paired, single-valued per
  locale, pivot-excluded; `localeCoverage.kinds` is RECOUNTED from the
  availability plane at build time ([AC8](#ac8-manifest-is-the-single-typed-source)),
  never copied. Consumers and tests derive URLs from the manifest; nobody

## 7. List-index shapes

`/data/{kind}.json` (and per-locale twins) — one envelope + flat rows
(r1 example: every value below is real, read from buildid 20318128 on
2026-08-26; the recount probes own the live numbers, these illustrate
SHAPE):

```json
{ "buildId": 20318128,
  "coverage": { "kind": "item", "locale": "en",
                "count": 2125, "namedCount": 1803 },
  "rows": [ { "id": "Gold", "name": "Krowns",
              "icon": "/cdn/v20318128/item/Gold.webp" } ] }
```

- Required per row: `id`; `icon` (`cdnIconPath` or null — null is the named
  explicit-missing state, rendered as an empty well, never captioned);
  `name` (resolved for the file's locale; omitted when that locale lacks the
  name — the UI then shows the id verbatim, which is data, not prose).
- Optional per row: the kind's declared facet fields (rarity as case-name
  string, typeId, tier, …) — exactly the fields each kind schema's
  `listEntry` enumerates; lists never carry full base records.
- `coverage.count` states how many rows the FILE holds — for a pivot index,
  every canonical row of the kind (item: 2,125 at r1); for a per-locale
  twin, the rows available in that locale (item `de`: 1,807 at r1).
  `namedCount` = rows carrying a resolved name in this locale (both derived
  from `namedLocales`/`fields` in the availability plane). Both are
  coverage-scope facts (publishable class); no freshness stamps, no health
  words ([DR-2026-08-22-numbers-stand-alone]).
- Row order: canonical id order (deterministic, diff-stable); consumers sort.
- Wave-1 honesty: list indexes exist for ALL 40 kinds from day one
  (every managed kind has canonical rows), but per-locale list twins exist
  only where overlays do — see
  [§12](#12-locale-coverage-scope-recount-governed).

Taxonomy index `/data/db.json` feeds the PT02 kind→type→subtype menu:
`{buildId, kinds:[{kind,count}], itemTypeTree:{roots:[…], children:{id:[…]}}}`
— derived from the `itemType__itemType` parentType edges (many:1,
edge totals live in the [RELATIONS.md](../extracted/RELATIONS.md#modeled-pair-index)
header, R-5) and per-kind availability counts. Structure pinned by the
schema's example.

## 11. Provenance field law (two classes, one whitelist)

Per [DR-2026-08-15] D2, [AGENTS.md](../../AGENTS.md) rule 3, and
[seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page)
citability clause — the API inherits the page's ban, not the repo's habits.

(r1) Scope precision: the law binds PUBLISHED documents. Within the contract
plane it is enforced against the PUBLISHED-side definitions only — every
kind's `baseRecord`/`listEntry` plus `list`, `tooltip`, `markers`,
`map.published`, `common` — NOT against `canonicalRow` (which models a
repo-plane row and legitimately carries `textKey`) nor against the
repo-plane documents of [§3](#3-planes-and-ownership-boundaries)
(`overlay`, `availability`, `maps.schema.json`).

- **Whitelist — the ONLY provenance carriers in any published document:**
  - the build-id carrier, EXACTLY ONE SPELLING per document root
    ([§2.1](#21-recount-protocol-r1)):
    - `buildId` (integer) — required at the root of every API document
      (lists, entities, tooltips, db.json);
    - `buildid` (integer, registry-native) — required at the root of the
      served map projection only, and `buildId` FORBIDDEN there;
  - `coverage` (object, required wherever the document scopes data:
    `availableLocales`/`namedLocales` on entity-bearing documents — the
    cross-locale link row + hreflang drivers
    ([localization-architecture §2](../../_foundation/localization-architecture.md#2-cross-locale-link-contract));
    `kind`/`locale`/`count`/`namedCount` on indexes; `pins` on marker types).
- **Banned from every published document**, in three enforcement classes
  ([AC5](#ac5-provenance-whitelist-is-structural) implements each):
  1. **Repo bookkeeping keys** (banned as accepted KEYS on published-side
     defs): `_meta` and everything it carries (`sourceSheet`, `container`,
     `emitted`, `columns`, `enums`, `keyRule`, `localeTextRoute`); `textKey`
     bridge objects (locale files publish RESOLVED strings); dig/gate and
     registry-bookkeeping vocabulary (`gate`, `coordinateGate`,
     `publicationPlane`, `provenance`, edge `mechanism`/`valid`,
     `source`, `sourceRef`, `coordinateRows`).
     Collision carve-out, derived from the corpus at build time: a name that
     is a REAL canonical column of that kind passes through verbatim —
     `tool` is a genuine column of `item` (type-17 props) and `recipe`
     (type-6 FK), so it is banned nowhere as a word and accepted exactly
     where `_meta.columns` declares it. No other member of this class
     collides with any canonical column name (verified across all 40 kinds'
     `_meta.columns` at r1).
  2. **Acquisition/source-identity VALUES** (banned as substrings anywhere
     in a published-side schema): harvest/pak paths (`res.pak`,
     `assets.pak`, `content.pak`, `map.pak`, `extracted/`, `harvest/`),
     `.cdb`, hashes (`sha256`, `adler`), license tags, commits, extractor
     identity.
  3. **Observation instants**: deliberately NOT published in wave 1 —
     nothing renders them, and [DR-2026-08-22-numbers-stand-alone] keeps
     stamps off user surfaces; the machine plane may add them later without
     breaking this contract (additive).
- Enforcement is structural: published-side schemas close their objects and
  compose the matching envelope variant;
  [AC5](#ac5-provenance-whitelist-is-structural) walks ACCEPTED keys
  (`properties`/`patternProperties`/`required` slots — naming a token inside
  a `description` or a banning `not`/`enum` construct is not accepting it)
  and scans published-side files for the class-2 substrings.

### AC3: Kind schemas accept the live canonical corpus (structure only)

```sh
import json, sys, pathlib, jsonschema, referencing, referencing.jsonschema

store = {p.name: json.loads(p.read_text(encoding="utf-8"))
         for p in pathlib.Path("contracts").rglob("*.schema.json")}

    [(name, referencing.Resource(contents=sch, specification=referencing.jsonschema.DRAFT7))
     for name, sch in store.items()])

for k in sorted(wave_kinds.MANAGED_KINDS):

        e = next(v.iter_errors(json.loads(ln)), None)

    assert not errs, (k, errs[:3])

print("AC3 ok:", total, "rows structurally valid")
PY
```
