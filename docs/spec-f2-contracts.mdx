## 3. Planes and ownership boundaries

Three artifact families meet at F2; the contract names each plane's owner
so no later piece edits across the line:

1. **Canonical repo plane** (stages 4–6 own bytes; F2 reads only):
   `extracted/data/<kind>.jsonl` (+ `_meta` line 1 —
   [spec-stages-datasets §3.2](spec-stages-datasets.mdx#32-canonical-layout--_meta-line-schema-unchanged-from-drafts)),
   `extracted/relinks/*`, `extracted/locales/*`,
   `extracted/relinks/locale_availability.jsonl`,
   `extracted/data/maps.json`.
2. **Contract plane** (F2 owns): JSON Schema draft-07 documents +
   one machine manifest under `contracts/` ([§14](#14-files-touched)).
   Schemas assert STRUCTURE (shape, types, enums, required, patterns) —
   never row counts, cell fidelity, or edge validity, which remain
   cdb_verify/validate_all territory.
3. **Published data plane** (stage 7 will own bytes; F2 pins shapes):
   the static, unauthenticated, CORS-open `/data/**` + `/cdn/**` trees
   served beside the site — the machine half of
   [seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page)
   and the satellite obligation of
   [FRAMEWORK §2.17](../../FRAMEWORK.md#217-overlay-satellite-per-project-option-overwolf-default).
   One data plane, two renders: the API never disagrees with the page.

Two contract-plane documents model REPO-plane artifacts on purpose so F2
acceptance is provable before any emitter exists: `overlay.schema.json`
(today's `extracted/locales/**`) and `availability.schema.json` (today's
`locale_availability.jsonl` rows). Repo-plane documents may carry repo
vocabulary; published-side documents may not ([§11](#11-provenance-field-law-two-classes-one-whitelist)).

## 4. Stable identity and the kind universe

- **Entity id** = the canonical dataset `id`, VERBATIM (case-preserving,
  never slugified) — the immutable join key of
  [localization-architecture §5](../../_foundation/localization-architecture.md#5-data-layer-obligations--what-every-pack-must-ship)
  item 1. Observed charset `[A-Za-z0-9_]` (dev pivot ids are accent-stripped
  French, recon §4). A prettier display slug MAY be added later as an extra
  field/redirect source; it never replaces the id, and any rename ships a
  301 map ([seo-standard §1](../../_foundation/seo-standard.md#1-url--information-architecture)).
- **Synthetic-id caveat**: `frescos`, `env`, `recipe` (sheet `craft`) have
  no native id column — their ids are the zero-padded row ordinals pinned by
  `_meta.keyRule`
  ([spec-stages-datasets §3.2](spec-stages-datasets.mdx#32-canonical-layout--_meta-line-schema-unchanged-from-drafts)).
  These are stable WITHIN a buildid; cross-build diffing keys them on
  content, not ordinal (E3 versioned-truth work, R5/R10 digs). Published
  payloads carry them unchanged; consumers must not treat them as
  game-native.
- **Kind universe of record** = the 40 managed kinds (importable, never
  retyped): `activity amb attribute battle bonus class condition confessions
  counter credits effect env fiefAdministration fiefAlignment fiefCondition
  fiefEvent fiefGoal fiefLaw fiefMission fiefPlace fiefPopulation frescos
  groupType icon input item itemType kingdom loot mission notify recipe
  region skill sound startChoice status trait tutorial unitPattern`.
- **Deferred kinds get no published endpoints in wave 1**: the
  HBSON-decoded corpora (`place`, `group`, `element`, `levelProps` →
  location-place / enemy group / npc-dialogue / poi-battle-scene), Steam
  `achievement`, `constant`, and subset views
  ([RELATIONS.md §Deferred kinds](../extracted/RELATIONS.md#deferred-kinds-not-promoted-by-stages-46)).
  Their schemas land with their promotion (wave 3), extending — never
  reshaping — the contracts here. Marker rows MAY already point at deferred
  kind names ([§9](#9-map-marker-payload-shape-for-mapsjson-marks)); such
  links resolve when promotion lands and stay honestly dangling before.
- **Locale segments** = the 8 non-pivot CLIENT codes, exact strings:
  `de es fr ko pl pt-BR ru zh`; pivot `en` is bare
  ([DR-2026-08-20-locale-urls]). BCP-47 presentation mapping (`zh`→`zh-Hans`)
  is a PT16 rendering concern and never enters URLs, file names, or
  payloads.

## 5. Per-kind JSON schema contract (base + locale overlay)

Split per [FRAMEWORK §2.2](../../FRAMEWORK.md#22-entity--base--locale-overlay):
the base record is locale-FREE structure; prose lives only in per-locale
text fields; a locale file never mixes languages
([localization-architecture §1](../../_foundation/localization-architecture.md#1-architecture-one-dedicated-page-per-entity-per-language)).

### 5.1 Files

- `contracts/common.schema.json` — shared `$defs`: `provenanceEnvelope`
  (`buildId` integer + `coverage` object — the ONLY provenance carriers,
  [§11](#11-provenance-field-law-two-classes-one-whitelist)), `coverage`
  variants (entity/index/map), `cdnIconPath`, `entityPointer`, `worldCoord`,
  locale-code enum, id pattern.
- `contracts/kinds/<kind>.schema.json` ×40 — one per managed kind, each
  carrying three `$defs`:
  - `canonicalRow` — the canonical dataset row AS IT EXISTS TODAY
    (structure only; typed through the [§5.2](#52-cell-type-mapping-canonical--published)
    table). Exists so acceptance is provable against the live corpus before
    any emitter exists.
  - `baseRecord` — the published record: `allOf` →
    `common.schema.json#/$defs/provenanceEnvelope`, plus `id` and every
    non-localizable column verbatim, enums RESOLVED to case-name strings,
    icon descriptor replaced by the CDN path. Optional localized text fields
    (`name`, `description`, other localizable columns as strings) are legal
    HERE and present only in locale files — one def serves the pivot base
    file and the per-locale resolved view. No `textKey` objects, no `_meta`
    internals, closed `additionalProperties`.
  - `listEntry` — the row projection consumed by kind list indexes ([§7](#7-list-index-shapes)).
- `contracts/overlay.schema.json` — pins TODAY'S repo-plane overlay
  artifacts: an object keyed by entity id, values
  `{name?, description?, <otherLocalizableColumn>?}`, all-string values.
  Pins the `desc`→`description` alias and the omit-until-translated omission
  rule ([locale-key-convention §2, §6](locale-key-convention.mdx#6-filler-policy-application)).
  Kind-generic; wave-1 files are its first instances; dig 14 extends
  instances, never this shape.
- `contracts/availability.schema.json` — pins TODAY'S availability row:
  `{kind, id, availableLocales[], namedLocales[], fields:{<locale>:{...}}}`
  ([locale-key-convention §3](locale-key-convention.mdx#3-emitted-artifacts)).
  Shape only; the row-count/locale-set law stays in
  `availability-regenerated`.

### 5.2 Cell-type mapping (canonical → published)

From the verified CastleDB type table ([cdb_census.py](../pipeline/tools/cdb_census.py)
header; codes verified against real payloads 2026-08-24):

| code | CDB meaning | canonical cell | published `baseRecord` |
|---|---|---|---|
| `0` | id | string | `id` (required) |
| `1` text, `kind:"localizable"` | game prose | `{"textKey":{bridge,sheet,column,row}}` or absent | omitted from the pivot base; resolved STRING in locale files only |
| `1` text (plain / `kind:"script"`) | literal text, hscript source | string | string, verbatim |
| `2` | bool | bool | bool |
| `3` | int | integer | integer |
| `4` | float | number | number |
| `5` enum-inline / `9` enum-custom | case index into `_meta.enums` | integer index (+ args for `9`) | case-NAME string (args verbatim) — enum resolution is an EMIT-stage transform, so the frontend never derives data (AGENTS rule 8) |
| `10` flags | bitmask over case list | integer | array of case-name strings |
| `6:<sheet>` | hard foreign key | referenced row id string | string, verbatim, original column name |
| `8` | list of sub-rows (`<parent>@<col>` hidden sheet) | array of objects | array, recursed through this same table |
| `11` | hex color | string | string |
| `13` / `16` | file / directory path into pak content | string | string, verbatim (game-internal join key — client paths are GAME data, not our acquisition path) |
| `14` | icon atlas descriptor `{file,size,x,y[,width,height]}` | object | REPLACED by `icon`: `cdnIconPath` or `null` ([§10](#10-icon-cdn-references)); raw descriptor never publishes |

Null cells are omitted at both planes (absent = null), per the canonical row
contract. Keys outside the declared schema (`__ignoreLoc__`, polymorphic
leftovers) pass through verbatim — doctrine Principle one.

## 6. Static JSON API URL architecture

The load-bearing rule of
[seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page):
an agent can act on this database iff it can fetch an entity's JSON at a
STABLE URL DERIVED FROM ITS PAGE URL and get the same facts the page renders.

**Derivation rule (bijective, mechanical):** take the page path, strip the
optional leading locale segment, prepend `data/`, append `.json`.

| surface | pivot page (EN, bare) | locale page | data URL |
|---|---|---|---|
| kind list | `/{kind}` | `/{L}/{kind}` | `/data/{kind}.json` · `/data/{L}/{kind}.json` |
| entity | `/{kind}/{id}` | `/{L}/{kind}/{id}` | `/data/{kind}/{id}.json` (base) · `/data/{L}/{kind}/{id}.json` (base + that locale's resolved text; filler policy applied by omission) |
| tooltip sub-route | `/{kind}/{id}/tooltip` | `/{L}/{kind}/{id}/tooltip` | `/data/{kind}/{id}/tooltip.json` · `/data/{L}/{kind}/{id}/tooltip.json` |
| DB landing + taxonomy | `/db` (PT02) | `/{L}/db` | `/data/db.json` (locale-free tree; labels resolve from overlays/chrome) |
| map registry | `/map` (PT05) | `/{L}/map` | `/data/map.json` (published PROJECTION of the registry — [§9](#9-map-marker-payload-shape-for-mapsjson-marks)) |

- Page-tree shape is pinned WITHOUT a `/db` prefix on entity routes (shorter
  canonical, kind-first hierarchy per
  [seo-standard §1](../../_foundation/seo-standard.md#1-url--information-architecture);
  FRAMEWORK's `/db/…` tooltip example is evidence shape, not doctrine —
  nw-site-new is reference, with listed deviations). One entity, one URL,
  forever ([FRAMEWORK §2.7](../../FRAMEWORK.md#27-url-architecture-is-the-product));
  adopting a prefix later is a rename with a 301 map, paid once.
- An entity unavailable in locale L (absent from `availableLocales`, per the
  bimodal availability law) has no L page AND no L data file — a true 404,
  never pivot prose ([filler policy](locale-key-convention.mdx#6-filler-policy-application)).
- **Site root composition**: paths here are root-relative. Today
  (localhost / standalone) the root is `/`; under the provisional umbrella
  placement it is `{hub}/games/wartales` — segments unchanged either way;
  domain placement stays owner-gated (Q1, [DR-2026-08-24-wartales-roster]).
- **Namespace disjointness (gated)**: the kind set, the locale set
  `{de,es,fr,ko,pl,pt-BR,ru,zh}`, and the reserved first segments
  `{data, cdn, db, map}` are pairwise disjoint — asserted mechanically in
  [AC7](#ac7-url-namespace-disjointness-and-derivation-bijection).
- No querystring locales; no pagination parameters on list indexes (each
  kind's index is one static file; largest is item at 2,125 rows — a
  tens-of-kilobytes artifact). The page-size-50 ruling
  ([DR-2026-08-18-page-size]) governs rendered listing pages, not data
  artifacts.
- `contracts/api.manifest.json` — the machine-readable form of this
  section: `{version:1, locales:{pivot:"en", prefixed:[…8…]},
  reservedPrefixes:[…], kinds:[…40…], surfaces:{list, entity, tooltip,
  taxonomy, map}, localeCoverage:{mode:"wave-1", kinds:["class","item",
  "skill"]}, derivationRule:"…"}`. Consumers and tests derive URLs from it;
  nobody retypes the table.

## 7. List-index shapes

`/data/{kind}.json` (and per-locale twins) — one envelope + flat rows:

```json
{ "buildId": 20318128,
  "coverage": { "kind": "item", "locale": "en",
                "count": 1807, "namedCount": 1807 },
  "rows": [ { "id": "Gold", "name": "Gold",
              "icon": "/cdn/v20318128/icon/Gold.webp" } ] }
```

- Required per row: `id`; `icon` (`cdnIconPath` or null — null is the named
  explicit-missing state, rendered as an empty well, never captioned);
  `name` (resolved for the file's locale; omitted when that locale lacks the
  name — the UI then shows the id verbatim, which is data, not prose).
- Optional per row: the kind's declared facet fields (rarity as case-name
  string, typeId, tier, …) — exactly the fields each kind schema's
  `listEntry` enumerates; lists never carry full base records.
- `coverage.count` states how many rows the file holds; `namedCount` how many
  carry a name in this locale. Both are coverage-scope facts (publishable
  class); no freshness stamps, no health words
  ([DR-2026-08-22-numbers-stand-alone]).
- Row order: canonical id order (deterministic, diff-stable); consumers sort.
- Wave-1 honesty: list indexes exist for ALL 40 kinds from day one
  (every managed kind has canonical rows), but per-locale list twins exist
  only where overlays do — see [§12](#12-wave-1-locale-scope-note-availability-regen-lands-with-dig-14).

Taxonomy index `/data/db.json` feeds the PT02 kind→type→subtype menu:
`{buildId, kinds:[{kind,count}], itemTypeTree:{roots:[…], children:{id:[…]}}}`
— derived from the `itemType__itemType` parentType edges (72, many:1,
[RELATIONS.md](../extracted/RELATIONS.md#modeled-pair-index)) and per-kind
availability counts. Structure pinned by the schema's example.

## 8. Tooltip sub-route payload

`/data/{L}/{kind}/{id}/tooltip.json` — the wowhead-model card feed
([site-sections §21](../../_foundation/site-sections.md#c-distribution--integration)),
consumed by hover jobs (PT04b), the embed lane, and third parties:

```json
{ "buildId": 20318128,
  "coverage": { "locale": "de", "availableLocales": ["en","de","fr"],
                "namedLocales": ["en","de","fr"] },
  "kind": "skill", "id": "Charge",
  "name": "Ansturm", "description": "…",
  "icon": "/cdn/v20318128/skill/Charge.webp",
  "stats": { "apCost": 3, "cooldown": 1 },
  "links": [ { "kind": "status", "id": "BleedingTarget", "name": "Blutung" } ],
  "url": "/de/skill/Charge" }
```

- `name`/`description` resolved in the file's locale; either may be omitted
  (bimodal availability + per-column drift populations are real,
  [locale-key-convention §5](locale-key-convention.mdx#5-drift-ledger--cdb-rows-with-no-bridge-leaf-anywhere)).
- `stats` = the kind's quotable subset — the SAME builder that fills the
  page's quotable answer block fills this object; divergence between tooltip
  and page is a defect (one data plane, two renders). Per-kind stat selection
  stays a permissive `object` in wave 1 and tightens per kind when PT04a
  lands — flagged, not designed, here.
- `links[]` = top inverted-relation neighbors with resolved names; sourced
  from the relink plane, capped (≤12) for payload size.
- `url` = the canonical PAGE url for this locale (round-trips the
  [§6](#6-static-json-api-url-architecture) derivation).
- The HTML twin `/{L}/{kind}/{id}/tooltip` renders the identical facts for
  humans/embedders; both come from one payload.

## 9. Map marker payload shape for maps.json marks[]

The registry layer `marker-layers` declares 15 marker types with `pins: 0`
and no rows yet. When the D11-validated coordinate families emit, they land
as `marks[]` inside that layer, and the PUBLISHED map artifact is a
projection of the registry:

- New file `contracts/markers.schema.json` pins the MARK ROW:
  ```json
  { "id": "A1BorderPost", "type": "border-crossing",
    "x": -1536.0, "y": 2048.0 }
  ```
  Required: `id`, `type` (enum frozen to the registry's 15-type vocabulary),
  `x`, `y` — WORLD units (128-unit cells), never pre-projected pixels; pixel
  projection is the viewer's job through the pinned `crs`/
  `coordinateTransform` blocks (`px=wx·4, py=wy·4`), so one transform stays
  authoritative. Optional: `regionId`, `entity {kind,id}` (the two-way
  entity link; `kind` draws from the 40 managed kinds PLUS the five reserved
  promoted-later names `place group element levelProps achievement`),
  `icon` (`cdnIconPath` or null), `label` (per-locale map whose values MUST
  come from the game's own localization; else null — marker prose otherwise
  lives in the linked entity's text and chrome i18n, never inline).
- New file `contracts/map.published.schema.json` pins the SERVED projection
  of the registry: registry structure with every repo-only field stripped —
  layer-level `source sourceRef provenance gate notes coordinateRows
  publicationPlane`, type-level `carrier coordinateGate`,
  `coordinateTransform.provenance/.validation`, and the dig-QA top-level
  blocks `expectedPayloadVocabulary`, `instanceMaps`, `storagePlanes` —
  and dataPlaneOnly imagery absent. `storagePlanes.served` ("albedo→webp
  tiles only") is exactly the publish set; splat/normal/height stay
  data-plane-only, catalogue-first per [DR-2026-08-18-media-scope]. Layers
  gain optional `marks[]` rows validated against `markers.schema.json`;
  allowed top-level keys: `buildid crs coordinateTransform layers regions
  battleTactical`.
- `contracts/maps.schema.json` (registry schema, committed) is NOT edited by
  F2; the additive `marks[]` revision to it rides whichever stage first
  emits marks, together with the map stage owner.
- Coverage honesty per family: the three unresolved coordinate slices
  (`encounter-spawn`, `vendor-npc`, `fief-district` — `unknown-P1` in
  [spec.md](../spec.md) `maps.coordinate-sources`) emit ZERO marks until
  their carriers land; `types[].pins` counts stay the published coverage
  statement. Battle-tactical remains a separate CRS family, out of the first
  slice (`battleTactical.crsType: "separate-family"`).

## 11. Provenance field law (two classes, one whitelist)

Per [DR-2026-08-15] D2, [AGENTS.md](../../AGENTS.md) rule 3, and
[seo-standard §9](../../_foundation/seo-standard.md#9-answer-engines-aeogeo--be-the-cited-answer-not-just-the-ranked-page)
citability clause — the API inherits the page's ban, not the repo's habits:

- **Whitelist — the ONLY provenance fields in any published document:**
  - `buildId` (integer, required at every document root);
  - `coverage` (object, required wherever the document scopes data:
    `availableLocales`/`namedLocales` on entity-bearing documents — the
    cross-locale link row + hreflang drivers
    ([localization-architecture §2](../../_foundation/localization-architecture.md#2-cross-locale-link-contract));

### AC7: URL namespace disjointness and derivation bijection

Kinds ∩ locales ∩ reserved prefixes = ∅; and for a deterministic sample
(first row id of every kind × {pivot, first locale} × {list, entity,
tooltip}), applying the manifest derivation rule to the page URL yields the
data URL, and the inverse mapping restores the page URL.

```sh
PYTHONIOENCODING=utf-8 python - <<'PY'
import json, sys, pathlib
sys.path.insert(0, "pipeline/tools"); import wave_kinds
m = json.loads(pathlib.Path("contracts/api.manifest.json").read_text(encoding="utf-8"))
ks, ls, rs = set(m["kinds"]), set(m["locales"]["prefixed"]), set(m["reservedPrefixes"])
assert ks == set(wave_kinds.MANAGED_KINDS)
assert not (ks & ls) and not (ks & rs) and not (ls & rs), "namespace clash"
def data_url(page):
    seg = page.strip("/").split("/")
    loc = seg.pop(0) if seg[0] in ls else None
    inner = ([loc] if loc else []) + seg
    return "/data/" + "/".join(inner) + ".json"
def page_of(data):
    seg = data.strip("/").split("/")
    assert seg[0] == "data"
    seg = seg[1:]
    loc = seg.pop(0) if seg[0] in ls else None
    return ("/" + loc if loc else "") + "/" + "/".join(seg)[:-len(".json")]
first_ids = {}
for k in sorted(ks):
    ln = pathlib.Path(f"extracted/data/{k}.jsonl").read_text(encoding="utf-8").splitlines()[1]
    first_ids[k] = json.loads(ln)["id"]
probe = sorted(ls)[0]
pages = []
for k in sorted(ks):
    pages += [f"/{k}", f"/{k}/{first_ids[k]}",
              f"/{k}/{first_ids[k]}/tooltip"]
pages += [f"/db", f"/map", f"/{probe}/db", f"/{probe}/map"]
for pg in pages:
    d = data_url(pg)
    assert d.endswith(".json") and "/data/" in d, (pg, d)
    assert page_of(d) == pg, (pg, d)
print(f"AC7 ok: namespaces disjoint, {len(pages)} page URLs bijective")
PY
```
