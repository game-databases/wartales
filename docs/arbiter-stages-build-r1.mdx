## Adjudications (mission items 2–4)

### R8 vs T4 — is `--buildid` on promote_drafts compliant?

**Compliant addition; the spec text lags.** §3.6's operative sentence is
"run_all passes defaults `BUILDID` on every invocation", written for the
retrofit as a whole; the emitter stamps relink `_meta.buildId` (emit
`:282`), and the promoter consuming it makes the promotion act
fail-loud-before-write on drift — the same doctrine §3.4 rules 3–6 serve
and strictly stronger than promoting then failing at the verify gate.
T4 pins §3.6 emit/verify semantics only; there is no contradiction.
Removing the flag or ignoring it would be the actual defect. **Fix is
doc-side:** amend the §3.1 step-4 and §4.1 step-1 command blocks and the
§3.4 CLI block to carry `[--buildid <id>]`, with one behavior-rule line
(draft `_meta.buildId` ≠ `--buildid` ⇒ exit 1 before any write).

### F3 — validator machinery or test-side assertion?

Neither extreme. A test alone cannot make the validator see MD falsification;
the marker alone cannot see it either (it binds matrix→MD one-way and survives
row edits). But regenerating render strings inside validate_all would couple
the checker to the producer's formatter — the thing its child-invocation
design avoids. Ordered middle: parse the Full-matrix section's **modeled**
cells (regex field extraction, T9's approach — an independent re-derivation)
and compare FIELD VALUES (status word, edges, validCounts triple, joinKeys,
cardinality) against the matrix records. 39 modeled directions today;
bounded. Plus the T10 fault leg that edits an MD row expecting
`catalog-parity=False`.

### F6 — where the fix belongs

The suite-side escalation (T2b hard under `--run-integration`) is correct
but treats the symptom. The spec puts the invariant IN the gate twice
(§3.3 "dangling must be 0 pack-wide"; §4.4 "any positive count fails
cdb_verify (exit 1) and therefore the stage"), and the landed verifier's
own docstring claims it. One `if dangling: fail(...)` line closes the gap
at the layer that owns it; T2b's probe then falls through to its
hard-assert arm naturally.
