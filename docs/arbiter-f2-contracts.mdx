## Mandatory cross-spec integration checks

### 4a — pageSegments key: **FAIL → N-1 (MAJOR)**

[F4 §2 r1b](./spec-f4-app-shell.mdx#2-locale-model--one-table-one-derivation)
(binding errata from the arbiter-pt16 adjudication, commit ca4d825,
07:05) freezes: *"The manifest's `locales` object therefore carries one
additive key: `"pageSegments": {"pt-br": "pt-BR"}` — key = page segment,
value = client code"* plus the three-way rule (member of `prefixed` → own
client code; member of `pageSegments` keys → mapped value; neither → not
a locale segment). F2 r1 (commit 3c4ec35, 07:38 — after the freeze)
pins §6's manifest as `{locales:{pivot, pagePrefixes[8], dataCodes[8]},
…}` and asserts exactly those keys in AC8. `pageSegments` appears nowhere
in F2 (grep: zero hits); neither does `prefixed`.

- **Direction**: consistent — both carriers map page segment → client
  code, and F2's positional pairing yields the identical `pt-br`→`pt-BR`
  mapping. This is a key/carrier divergence, not a semantic reversal.
- **Consequence**: a builder following F2 §6 literally emits a manifest
  that violates frozen F4 (its documented consumers resolve through
  `pageSegments`); a builder following F4 literally fails F2 AC7/AC8
  loudly (KeyError on `dataCodes`). A superset manifest would satisfy
  both letter-for-letter — no F2 AC forbids extra keys and F4 declares
  its key additive — but NO text authorizes that merge, so conformance
  would rest on the builder reading two specs and inventing the union.
- **Whose text wins**: F4's. It is the binding errata produced by a
  recorded arbitration, it was frozen before F2 r1 landed, F2 r1 cites
  F4 §2 without engaging its r1b manifest law, and F2's conflicts entry
  claims "RESOLVED ON THE F2 SIDE … no F4 edit needed" while silently
  substituting the mechanism. Frozen authority outranks a later silent
  reshape of the same artifact.
- **Same-root second consequence**: PT16 quotes F2's derivation rule
  "stated verbatim" in two places ([§8.2 subjectOf](./spec-pt16-seo.mdx#82-json-ld-graph)
  L387-393 and [§9.4 llms.txt](./spec-pt16-seo.mdx#9-llmstxt--the-agent-entry-contract)):
  *"take the page path, strip the optional leading locale segment,
  prepend `data/`, append `.json`"* — the PRE-r1 one-segment-set rule,
  with no mapping leg. Applied to `/pt-br/item/Gold` it composes
  `/data/pt-br/item/Gold.json`, outside F2's declared set. PT16 is
  frozen and its actual link generation consumes the manifest (so
  emitted links will be correct once the manifest is unambiguous), but
  the stale verbatim quote must be recorded in F2's conflicts section —
  its PT16 entries cover localeCoverage and lastmod spellings and miss
  this entirely.
- **Prescribed fix (all F2-side, ~10 lines)**: add
  `pageSegments:{"pt-br":"pt-BR"}` to §6's manifest shape, DERIVED FROM
  and asserted-equal to the positional pairing (one AC8 assertion);
  state in §6 that `dataCodes` is the successor of the key F4 r1b calls
  `prefixed` (same 8 client codes, same semantics); record both the
  rename and the PT16 quote staleness in `## r1 conflicts`. No other
  section moves; all ACs stay executable.
