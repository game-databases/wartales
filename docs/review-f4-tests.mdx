## Axis 2 — vacuous-assertion hunt (mutations tried)

**M-A (empirical, decisive).** Copied the hygiene suite into a scratch
sweep-layout with a component containing only
`bg-gray-900 text-zinc-100 border-neutral-700 hover:bg-slate-800 from-stone-200`:
**suite passed 11/11 GREEN** against a visibly palette-broken shell.

**M-B (selectivity proof).** Same fixture plus `p-4 gap-2 rounded-lg`:
numeric-spacing and rounded-corner went red while "has zero stock-palette
classes" stayed green with the violations in the same className string.

Root cause — `site/src/styles/shell-hygiene.test.ts:86-92`:

```ts
const STOCK_PALETTE = /^(?:slate|gray|zinc|neutral|stone)-(\d{2,3})$/;
function paletteHit(tok) { const m = STOCK_PALETTE.exec(baseClass(tok)); … }
```

The regex is anchored over the *whole* post-normalization token, and
`baseClass()` strips variant/opacity/important syntax but never the utility
prefix — so it matches only a bare `gray-500`, which is not valid Tailwind;
every real spelling (`bg-gray-900`, `text-zinc-300`, `dark:bg-gray-800`,
`from-stone-200/50`, `ring-zinc-500!`) misses. Function-replica probe
confirms all eight realistic spellings return false. Sibling laws using the
same tokenizer work (probe: `p-4`, `gap-2`, `hover:p-8`, `rounded`,
`md:rounded-xl` all caught; `p-g4` correctly allowed).

Everything else hunted came back sound:

- **No mocks exist** in any suite — these are real-artifact suites over
  files and HTTP; the "mock that always passes" class is absent by design.
- Missing-fixture poisoning is exemplary: a missing sweep target pushes a
  `sweep-target` violation that **poisons every `fail()` call**
  (shell-hygiene.test.ts:203-211, 348-361) — demonstrated accidentally when
  my first scratch copy lacked `src/components/`: all 10 laws red, not
  vacuously green. `needRows()/needLoaded()/needEntries()` guards do the
  same for the other three suites; discovery helpers fail loudly naming what
  they looked for.
- Absence laws over absent targets are guarded: manifest must be non-empty
  and well-formed before the `/en`+`/search` absence loop runs;
  `lang-attrs` fails (not passes) on an empty pages map
  (smoke.mjs:291). Residual: seven later legs lack that empty-map guard —
  if all nine root fetches threw (server died mid-run) they would print
  vacuous PASS lines while `roots-nine` still fails the verdict — contained
  dishonesty, filed as m-2.
- Loop-over-empty-set traps: chrome-parity iterates loaded files behind
  `needLoaded()` (throws on any load error); routes-manifest labelKey loop
  requires ≥1 entry first. No vacuous loops found beyond m-2.
- Regex-matches-everything: none found; conversely M-1 is
  regex-matches-nothing. Adjacent nit: `VAR_FORM`
  (shell-hygiene.test.ts:136) accepts `var(--bg-1, #100F0E)` — a literal
  smuggled through a fallback survives the canon-literal gate for
  canon-named props outside the `GAME_EXACT` enumeration (the enumerated
  rows' exact() check would still catch their own names) — m-5.
- Contrived: `flatten()` coerces JSON `null` values to the string `"null"`,
  which passes the non-empty gate (chrome-parity.test.ts:54-62) — m-8.

## Axis 3 — blind-law integrity

Kept at contract level almost throughout. The suites hardcode the §2 table,
§4 inventory, and the one-row manifest fixture as expected values (pinning,
correct); tolerant shape-discovery in the two blind-prone suites accepts
reasonable spellings and otherwise fails loudly — exactly what a blind pair
needs. Faithful external-contract anchoring: `noto-cjk` greps for
Google-hosted Noto Sans SC/KR split-subset links because the fonts README
(lines 58–63) prescribes exactly that pattern. Two overreaches:

- m-9: `search-slot-staged`'s post-mount branch invents F5 internals —
  requiring an `<input>` or `<button>` inside whatever F5 mounts
  (smoke.mjs:461-465). r2b staged semantics ("exactly the F5 field host")
  are honored, but the affordance guess can false-red after F5 lands. The
  r2b errata exists precisely to prevent post-F5 false reds; this heuristic
  partially reintroduces one.
- m-4: locale-routing's static half of the unknown-segment law greps
  `/notFound\s*\(/` in request.ts source (locale-routing.test.ts:335-346) —
  satisfiable by a comment, and "before message resolution" ordering is not
  statically provable. The dynamic half (`/xx/foo` → 404, verified live)
  covers the outcome, so this stays MINOR.

Also noted, not defects: `PIVOT_KEYS` flag check is conditional on some row
carrying a flag (locale-routing.test.ts:254-262) — acceptable under declared
shape tolerance since the load-bearing `defaultLocale === "en"` assertion is
unconditional.

## Axis 4 — smoke runner correctness

**Guard honesty: verified honest.** Disarmed run prints per-leg SKIP lines
with the arming instruction (smoke.mjs:646-656), still executes the
dev-server-free `stage-check-pair` (line 677), and exits 0 — matching the
documented contract. No disarmed path prints PASS except the genuinely
server-free stage pair. Verdict line reports skip counts explicitly. Exit
codes verified empirically in both directions today: disarmed → 0; boot
failure → recorded FAIL → exit 1; crash handler exits 1.

**The disputed pivot-301 ruling: the CodeWriter's claim is CONFIRMED.**
Old line: `(res.headers.get("location") ?? "").replace(/\/$/,"")`. For the
conformant response to `/en` the Location IS `/`; stripping its trailing
slash yields `""`, compared against `wantLoc("/en") === "/"` → permanent
false FAIL for ANY conformant app. Demonstrated live: this shell answers
`301 Location: /` (curl above). The fix
(c4f312f, smoke.mjs:305-309) — strip one trailing slash only when
`raw.length > 1` — preserves `/`, still normalizes `/fr/` → `/fr`, still
fails a missing Location (`"" ≠ "/"`) and query-bearing mismatches. Minimal
(two lines + explanatory comment), faithful (adds no leniency), and it did
not touch any other leg. Cross-pair propriety is the Code Reviewer's axis;
from the test-integrity seat the edit improves the suite.

Leg-quality notes: `pivot-301` generalizes AC 3's two examples to all nine
targets and asserts permanence + Location each — stronger than spec letter.
`assets-resolve` SKIP honesty is genuine: unstaged binaries produce explicit
per-ref SKIP lines; staged-but-unfetchable is a FAIL; staged machine whose
documents declare zero refs is a FAIL (wiring defect), unstaged machine zero
refs is an honest defer.

## Axis 5 — suite hygiene

- No `vitest.config.*` added (verified absent); `test: vitest run`
  byte-present; zero-config discovery confirmed by the run output listing
  all five files.
- Canon untouched: `git log e82d8a1..HEAD` shows zero commits touching
  `tokens.css`/`tokens.test.ts`; canon suite passes 24/24 unmodified.
- Imports: suites use only `vitest`, `node:*`, and relative paths — no `@/`
  alias (which would require config that must not exist).
- Placement: three suites beside their subjects under `src/**` per §7 —
  but `chrome-parity.test.ts` sits in `site/messages/`, violating §7's
  header law ("beside or under `site/src`"). It IS discovered by the
  zero-config run, so the violation costs nothing mechanically — m-6.
- Flaky-timing traps: none of the node:test `after()` class — setup is
  `beforeAll`-only, no global temp state, fixtures deterministic. The
  adjacent trap lives in the smoke teardown/cleanup path — m-7:
  `killTree` fires `taskkill /T /F` without awaiting or verifying
  (smoke.mjs:211-221), `freePort` has the usual bind-close-spawn TOCTOU
  (73-83), and Next 16's one-dev-server-per-dir lock means any foreign or
  leaked dev server turns every subsequent armed run into a
  `boot-reachable` FAIL. That failure mode was observed live during this
  review (orphan PID 60820 on :3777 from an earlier session; my armed run
  failed honestly within seconds with the cause in the log tail). A leaked
  server from the runner's own past runs would poison future runs the same
  way — hence a flaky-cleanup finding, not just an environment note. My own
  run leaked nothing (port-table diff before/after: none).
