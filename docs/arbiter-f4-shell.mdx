- **B1.** The added catch-all is the correct Next.js App Router mechanism:
  a nested `not-found.tsx` alone never matches a URL; with
  `app/[locale]/[...rest]/page.tsx` calling `notFound()` inside the
  segment, `/de/<unknown>` reaches the locale-scoped boundary. File-set
  closure restored (§9 Created lists the catch-all), so the builder
  cannot be accused of silent additions. The unknown-locale case is
  stated honestly — "an unknown-locale request answers its 404 from the
  root boundary — there is no localizing a locale that does not exist"

  what can exist. Amended AC 14 is executable as written: smoke curls
  `/de/<unknown>` and asserts 404 + localized chrome + `<html lang="de">`.

  "the wrapper holding page content between header and footer";

### N1 — MINOR: the aliasing-law carve-out contradicts the canon it names, and the non-color slice of the loophole stays open (§6.2)

§6.2: "Literals are allowed only for scalars the canon does not define
(`--radius-*: 0`)". tokens.css L167–171 defines exactly that family —
`--radius`, `--radius-sm/md/lg/xl`, all `0rem` — so the carve-out's own
example names canon-defined scalars, and the shell-hygiene predicate as
specified bans only "any hex/rgb/oklch/named-color literal" inside the
`@theme` block. Consequence: a literal copy of a canon-defined
non-color value (a radius length, or a font stack for the six `--font-*`
mappings §6.2 lists without stating right-hand sides — where the
aliasing form's own examples don't apply because the theme-namespace
name equals the canon name) passes every stated command while
duplicating a canon value. Today this is behaviorally inert — canon
radius is 0, tokens.test.ts pins `parseFloat == 0`, and import order
keeps tokens.css authoritative — which is why M3 stands RESOLVED and
this does not gate. Required touch-up (one of, builder's first pass or a
one-line spec edit): drop `--radius-*` from the allowed-literals example
(require omission — Tailwind resolves the utilities from tokens.css's
`:root` values — or an explicitly pinned form), and/or extend the
shell-hygiene grep to any non-`var()` literal whose left side matches a
canon token name.
