## 1. Freeze-policy ruling (asked for explicitly)

**Regenerate-at-run wins for every machine-layer number in this spec.**
The freeze source IS `cdb_emit.py`'s regeneration output from
`extracted/harvest/res/data.cdb` at the pinned buildid — *not*
"`_draft/` as found on disk". This distinction is the whole of B1: the
spec froze honest numbers at authoring time (~05:58), Dig 7 then
post-processed the same draft bytes in place (~07:14), and both the spec's
"counts re-measured on disk" phrasing and the reviewer's reading treated
the post-processed directory as the referent. It is not. Proven above:
regeneration reproduces **exactly** the spec's frozen set (40 / 10,207 /
51 / 19,130 / 0 dangling / 72 null decomposing 61+9+2) and the verifier
passes clean over it. Numbers derived from emitter output are stable
across every rerun at this buildid; hand-post-processed bytes are dig
evidence, not freeze sources. A future patch re-freezes per
EXTRACTION-LOG §5, from a fresh regeneration.

Freeze-and-bump remains correct only for numbers describing artifacts no
stage regenerates (none exist in this spec after fix F3 removes the one
such case).
