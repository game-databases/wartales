## Axis 2 — vacuous hunt

`len(d1)==10`, `doc["rows"]` truthy, `checked > 0`, `walkedSourceFiles > 0`,

## Axis 4 — the strict-xfail encoding

One function, `test_letter_divergences_stray_inputs_exit_2`, marked
`xfail(strict=True)` carries both divergences: (a) §9 item 5's "kind outside
SEARCHABLE_KINDS refused (exit 2)" vs measured filter-and-exit-0; (b) §3.1's
locale-set gate vs a stray overlay-only `ja/` dir being ignored. Judgment:

- **Encoding is right.** `skip` would stop executing the probe entirely;
  assert-opposite would enshrine the divergence as law and force a spec
  fight to change behavior; strict-xfail keeps executing, keeps the spec
  letter as the recorded expectation, tolerates today's measured reality,
  and FAILS THE SUITE the day the letter is adopted — with a reason string
  that contains its own removal instruction and the companion-test update
  obligation. Verified empirically via XFPROBE above: `[XPASS(strict)]`
  bites, and takes `test_non_searchable_kind_never_reaches_the_artifact`
  down with it exactly as coordinated (that passing test pins artifact
  purity positively, so the important invariant never rides the xfail).
- **Probe evidence checks out independently**: I traced both claims in the
  emitter source (the emit loop's kind filter; the consistency gate iterating
  the nine-key loaded dict rather than the directory) and reproduced both
  behaviors by subprocess.
- **Granularity residual (M-2)**: two divergences share one marker, so
  partial adoption (one leg conformant, one not) still reports XFAIL and is
  invisible. Two separate strict-xfail tests would let each divergence flip
  its own marker. Cosmetic today — full adoption provably fails loud — but
  cheap to split.
