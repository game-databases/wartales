## R1 — BLOCKER: validate_all crashes on a non-managed canonical file

Two defects, one root class ("dict lookup keyed by the managed universe"
fed by an unfiltered listing):

1. **The guard is vacuous.** `preconditions()` computes `have` via
   `managed_kinds_in()` (`validate_all.py:46–50`), which pre-filters to
   `wave_kinds.MANAGED_KINDS`. Therefore `extra = [k for k in have if k
   not in want]` (`:64`) can never be non-empty — a planted
   `place.jsonl` sails through the "exactly the 40 managed kinds" check
   (`:59–68`).
2. **The loop is unfiltered.** The census loops iterate ALL top-level
   `.jsonl` (`:147–151`), so the intruder enters `per_kind_rows`, and
   `census-per-kind` does `sheet = wave_kinds.KIND_SHEETS[kind]`
   (`:175`) → `KeyError`.

Proof (sandboxed repro, stubbed children, temp datadir seeded with copies
of the real 40 kinds + a planted `place.jsonl`):

```
File ".../pipeline/tools/validate_all.py", line 175, in main
    sheet = wave_kinds.KIND_SHEETS[kind]
KeyError: 'place'
```

Consequences, per contract:

- §5.2 requires every fault to become a report record `{id, expected,
  actual, pass}` with exit 0/1 semantics — instead: no report written,
  traceback, interpreter exit 1. Indistinguishable from a check-failure
  except by the absence of the file write.
- T10's contract ("planted `place.jsonl` … flips exactly its named check
  and exits 1") cannot hold: the crash precedes `hbson-independent`.
- Secondary corruption when the crash is avoided: `total_rows` (`:152`)
  counts the intruder, so `census-closure` would report a wrong number
  as a *check failure* rather than routing the intruder to its own record.
- Sibling scan of every dict lookup keyed by the managed universe:
  `cdb_verify.CENSUS[sheet]` (`:176`) is safe (sheet comes from
  `KIND_SHEETS`, all 40 sheets present — verified);
  `relink_catalog.py:159–160` uses `.get`; `promote_drafts.py:116` uses
  `.get`; the `run_all.ps1` embedded preconditions build their name list
  UNfiltered (`run_all.ps1:210`, `:237`) and correctly detect extras.
  Only `validate_all.py` has the bug.

Masking note (facts, not mitigation): through `run_all.ps1 emit` the
intruder IS caught — `Test-EmitPreconditions` (`run_all.ps1:227–260`)
checks raw names and exits 2 naming `run_all.ps1 datasets` before any
child runs. The crash is reachable via isolated `validate_all.py`
invocation, which is exactly the surface T10 exercises.

Fix (two moves, ordered by the spec's own layers):

- Keep run_all's exactly-40 die() as the stage-boundary guard (already
  correct). In `validate_all.preconditions()`, do NOT die on extras —
  per T10 the planted-file fault must reach the checks as a record.
- Filter the `:147` loop to `MANAGED_KINDS` for closure/per-kind math,
  and extend `hbson-independent` to enumerate every non-managed
  top-level `.jsonl` (fail on the four banned HBSON names per AC4/AC11;
  count-and-report the rest).
