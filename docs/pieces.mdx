# Wartales site — piece decomposition (orchestrator sequencing artifact)

The app broken into the smallest pieces that can be improved and judged
on their own (promptForDB decomposition directive). Each piece enters
the build pipeline only through a PrepareTask spec
(Documentator → Reviewer → Arbiter), then CodeWriter+TestWriter →
CodeReviewer+TestReviewer → Arbiter → fix loop, then the per-page-type
visual critic loop (`design-standard.md` §4: proposals are per page
type, never one monolithic restyle).

Data-dependency column marks what must exist in `extracted/` before the
piece can build past stub state (AGENTS.md rule 8 — frontend consumes
contracts, never derives data).

## Sequencing law

P0 scouts → spec freeze → F2/F3 → P1 extraction waves → rule-8 gate →
F4/F5 + PT16 skeleton → PT03/PT04 (DB core) → PT05/PT06 (map) → PT07
(builder) → calculators → content sections → UGC → critic loops per
page type throughout, e2e smoother between major waves.
