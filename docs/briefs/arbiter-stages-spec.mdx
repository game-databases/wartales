## Mission

Rule on every reviewer finding — the reviewer can be wrong. For each:

1. **Re-measure disk yourself** (counts, file existence, verifier runs).
   Ground truth moved during the review window; neither artifact's numbers
   are automatically current. State what YOU measure now.
2. VALID / INVALID / PARTIAL per finding, each with proof (command output,
   byte counts, cited lines).
3. Hunt holes in the REVIEWER's own judgments: where is its reading of the
   spec uncharitable or its "contradiction" actually resolvable by a
   wording change rather than redesign?
4. Over-engineering check: does any proposed fix exceed doctrine
   requirements ([DR-2026-08-17-relink] bars, [DR-2026-08-18-pipeline]
   one-command reproducibility)? Existing spec text wins where the
   proposed change is churn.
5. Boundary check: scope creep or silently weakened requirements on
   either side.
6. Verdict: APPROVE-FOR-BUILD, or REVISE with an ORDERED fix list
   (each item: exact section, exact required change, acceptance proof).
   Where concurrent digs invalidated frozen numbers, rule HOW the spec
   must pin them (regenerate-at-run vs freeze-and-bump) — do not leave it
   to the fixer's taste.
