## Verdict: SEND-BACK

Narrower than r2, and for one reason only — and this time the round
**cleared every condition of the re-entry bar**. The two carriers render,
the chrome is real, the uncommon slot is nameable, the hover outline is in
the pixels. Say it plainly: this is the first round I would believe is
Wartales. The send-back is for a defect my protocol caught only because
this round finally rendered enough truth to check: **the staged "700"
binary is byte-identical to the 400** — `cmp` says so, and a render A/B
(prove below) shows every bold run in the preview is Skia *synthetic* bold
smeared over 400 glyphs. r2 sent back a specimen that printed "IM Fell
English" over Georgia glyphs — a false claim in the render. A font file
named `eb-garamond-latin-700-normal.woff2` that is the 400 cut is the same
defect class one layer down: a false claim staged into the contract the
site will ship. The game's own UI carries a real bold
(`eb_garamond_bold.fnt`, per the README table); the staging was mandated to
deliver it ("Real font files rendering"); it delivered a photocopy.

### The defect, proven

1. `cmp site/public/fonts/eb-garamond-latin-400-normal.woff2
   site/public/fonts/eb-garamond-latin-700-normal.woff2` → byte-identical
   (44,336 B both; the italic and latin-ext files are distinct, as is IM
   Fell — only the 700 collides).
2. Render A/B (`_r3zoom/z-boldtest.png`): the same string at 400 and at
   700 with these files — the 700 line is visibly *heavier*, which is
   Chromium synthesizing faux bold because the binary's real weight class
   is 400 under a 700 declaration. A true 700 instance would be a
   different cut with different outlines; a same-bytes file cannot
   produce one.
3. Consequence in `preview-r3.png`: "Warden Helm", every stat value, the
   set counter, and the price render faux — the game's tooltip hierarchy
   rides a bold axis this preview does not actually have.
