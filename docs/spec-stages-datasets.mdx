## 0. Scope in one line

Flip run_all stages 4–6 from stub to BUILT: **datasets** promotes the
verifier-proven `_draft` wave-1+2 corpora to canonical
`extracted/data/<kind>.jsonl`; **relink** promotes the 51 hard-edge seed

and lands one machine-readable `extracted/validation-report.json` whose

criterion holds **without** the HBSON decode (that dig runs parallel; its
kinds arrive later as wave 3 — [§9](#9-out-of-scope)).

## 3. Stage contract — stage 4 `datasets`

### 3.1 Pipeline (exact commands, in order, stop-on-first-nonzero)

`$Cdb` = `extracted/harvest/res/data.cdb` (defaults-block key `CDB`,
[§6](#6-run_all-wiring-extraction-log-edit-list)); `$BuildId` = defaults
`BUILDID`; paths pack-relative (run_all does `Set-Location $PackRoot`):

```
1. python pipeline/tools/cdb_emit.py    <Cdb> --wave wave1 --buildid <BuildId>
      --outdir extracted/data/_draft --reldir extracted/relinks/_draft
2. python pipeline/tools/cdb_emit.py    <Cdb> --wave wave2 --buildid <BuildId>
      --outdir extracted/data/_draft --reldir extracted/relinks/_draft
3. python pipeline/tools/cdb_verify.py  <Cdb> --datadir extracted/data/_draft
      --reldir extracted/relinks/_draft --buildid <BuildId>          # GATE
4. python pipeline/tools/promote_drafts.py --plane data --buildid <BuildId>
      --datadir extracted/data/_draft --reldir extracted/relinks/_draft
      --out-data extracted/data                                      # WRITE
5. python pipeline/tools/cdb_verify.py  <Cdb> --datadir extracted/data
      --reldir extracted/relinks/_draft --buildid <BuildId>          # GATE
```

Steps 1–2 regenerate the draft corpus deterministically (row content is a
pure function of data.cdb; only `_meta.emitted` differs run-to-run — see the
idempotency rule in [§3.4](#34-promotion-tool-promote_draftspy)).
Step 3 is the **verifier gate: canonical write happens only after it exits
0** (`ALL CHECKS PASSED`). Step 4 is the only step that touches canonical
paths. Step 5 re-runs the same independent verifier over the promoted plane
to prove promotion fidelity (canonical data × draft seeds multiset equality).

Non-managed entries may lawfully sit in either `_draft` dir; stages 4–6
never clean, promote, or delete them. The promoter **ignores and enumerates**
each on stage stdout (file + reason — arbiter F1), and `cdb_verify` skips
them by the same managed universe
([§3.3](#33-what-the-verifier-gate-asserts-existing-cdb_verify-unchanged-semantics),
[§3.4](#34-promotion-tool-promote_draftspy) rule 1).

Exit codes surfacing through the stage: cdb_verify `1` on any failed check;
promote_drafts `1` drift/stale-tripwire, `2` missing precondition; anything
nonzero stops the stage and propagates (map-stage behavior).

### 3.2 Canonical layout + `_meta` line schema (unchanged from drafts)

Canonical dataset file = `extracted/data/<kind>.jsonl`; line 1 `_meta`, then
one JSON object per row, UTF-8, LF, `ensure_ascii=False`. The `_meta` schema
is the emitter's existing contract (verbatim fields, verified per file by
cdb_verify):

| field | meaning | example |
|---|---|---|
| `kind` | spec kind name | `recipe` |
| `sourceSheet` | CDB sheet emitted | `craft` |
| `buildId` | client buildid string | `"20318128"` |
| `container` | source container pin | `res.pak:/data.cdb (CastleDB JSON, compress=false)` |
| `rowCount` | data lines that follow | `667` |
| `emitted` | ISO timestamp of the emitting run | `2026-08-24T20:55:16` |
| `tool` | emitter path | `pipeline/tools/cdb_emit.py` |
| `localeTextRoute` | locale-routing note stamped on every dataset by the emitter (`cdb_emit.py:231`; present in all 40 regenerated `_meta`, measured 2026-08-25) | `lang/export_<locale>.xml via textKey refs; leaf addressing pinned by next dig` |
| `columns[]` | `{name, typeStr, opt, kind}` per column == CDB schema | |
| `enums` | case tables per enum/flags column (clash-disambiguated `sheet@col`) | |
| `keyRule` | ONLY on the three id-less sheets | `synthetic: zero-padded row ordinal — sheet \`craft\` has no id column` |

Row contract (pinned by digs 1–3, enforced by cdb_verify per cell): ALL
original columns under original names; null cells omitted (absent = null);
localizable text as structured `{"textKey": {bridge, sheet, column, row[, subSheet]}}`
refs — prose lives in the lang bridge; `6:` ref cells verbatim; keys outside
the declared schema preserved verbatim (`__ignoreLoc__`, polymorphic
leftovers); identifiers never stripped (doctrine Principle one). The
canonical dir also holds the map stage's products (`maps.json`, `cells/`) —
not `.jsonl`, never touched by this stage.

### 3.3 What the verifier gate asserts (existing cdb_verify, unchanged semantics)

Per dataset: `_meta` contract (buildId, rowCount, tool, columns == CDB
schema); row count == doc-side census count == source-sheet line count; id
sequence (native `"0"` column or documented `keyRule`); cell fidelity
(textKey refs exact — no prose leaks; refs verbatim; lists recurse; deep
equality elsewhere); schema ⊇ payload per row (nothing dropped); no invented
keys beyond the synthetic `id`. Per relink file: edge multiset == recount of
populated `6:` cells walked independently; per-edge `valid` recomputed
(`True` strict membership / `False` dangling / `None` datafile-backed-or-
hidden target); dangling must be 0 pack-wide; wave-1 totals cross-checked
against the dig-log table. **Scan scope** (arbiter F1) comes from the shared
kind-universe module ([§3.4](#34-promotion-tool-promote_draftspy) rule 1):
only the 40 managed kinds are verified; a datadir `.jsonl` outside the
universe, or a reldir file not named `<from>__<to>.jsonl`, is skipped and
enumerated, never failed (hole 1's name rule covers the relink side).
Sharing no code with the emitter is the point —
the gate is an independent re-derivation, not a diff of two runs of one
implementation; sharing the kind LIST does not dilute that (it is
membership metadata only), sharing derivation code would.

### 3.4 Promotion tool (promote_drafts.py)

New stdlib-only CLI (Python 3.14, NE8K `C:\Python314`):

```
python pipeline/tools/promote_drafts.py --plane data|relinks|both
    [--buildid <id>] [--datadir extracted/data/_draft]
    [--reldir extracted/relinks/_draft] [--out-data extracted/data]
    [--out-relinks extracted/relinks]
```

Behavior contract:

1. **Scope guard — the managed universe is defined (arbiter F1)**: the
   managed set is exactly the **40 kind↔sheet pairs of `cdb_emit.WAVES`
   waves 1+2**, carried as membership metadata only (kind↔sheet names and
   the `craft`→`recipe` mapping) in a neutral module,
   `pipeline/tools/wave_kinds.py`, consumed by `promote_drafts` (this
   whitelist), `validate_all` (per-kind checks), and `cdb_verify` (scan
   scope; it keeps its own census transcription and all derivation logic
   independent). `--plane data` manages exactly `<kind>.jsonl` for those 40
   kinds in out-data; `--plane relinks` manages exactly `<from>__<to>.jsonl`
   pair files in out-relinks. Never touches `maps.json`, `cells/**`,
   `locale_availability.jsonl`, or anything else — the co-located products
   of other stages are invisible to it (name-pattern whitelist, not
   blacklist). Non-managed draft entries are **ignored and enumerated** on
   stage stdout (file + reason): `achievement.jsonl` (Dig-10 keyless Steam
   emission — wave-3 promotion decision),
   `place`/`group`/`element`/`levelProps`.jsonl (Dig-7 HBSON decode — wave
   3), and the D7 other-plane products `worldmap_overlays.json` +
   `poi_coordinates.jsonl` ([§4.1](#41-pipeline-exact-commands)).
2. **Equality rule (idempotency)**: candidate draft file vs canonical target
   compare equal iff payload lines (line 2…) are byte-equal AND `_meta`
   equals except the `emitted` timestamp, which is exempt. Equal ⇒ skip
   (target untouched, mtime preserved, counted `unchanged`). Different ⇒
   replace atomically: write `<target>.part` then `os.replace` (spec-harvest
   §3.2 precedent), counted `updated`.
3. **Stale tripwire**: an existing managed-name canonical file ABSENT from
   the verified draft set ⇒ exit 1 naming the file; never deleted, never
   renamed (patch-drift signal handled by the EXTRACTION-LOG §5 re-pin
   procedure — same fail-loud doctrine as map AC8).
4. **Precondition**: referenced draft file missing ⇒ exit 2 naming it (the
   gate order in [§3.1](#31-pipeline-exact-commands-in-order-stop-on-first-nonzero)
   makes this unreachable through run_all; it protects isolated invocation).
5. **Provenance**: promoted bytes ARE the verified draft bytes — canonical
   `_meta.emitted` stays the moment those rows were computed from data.cdb;
   the promotion act itself is recorded in stage stdout (`unchanged` /
   `updated` counts) and the commit's EXTRACTION-LOG history entry.
6. **Deletion semantics — one per class (arbiter F5)**: managed planes
   **restore-and-pass** on deletion — a managed-name canonical target
   missing while its draft exists is recreated from the draft (counted
   `updated`, exit 0): drafts are the declared source of truth (rule 5's
   provenance logic) and the corpus is fully reproducible from `data.cdb`.
   Fail-loud stays where it belongs: ghost/stale managed-name canonical
   files absent from the draft set tripwire at rule 3 (exit 1 naming the
   file), and *consumer* boundaries fail loud through preconditions
   ([§4.1](#41-pipeline-exact-commands)/[§5.1](#51-pipeline-exact-commands),
   exit 2 naming the owning stage). Regenerated stage products
   (`locale_availability.jsonl`, `RELATIONS.md`, `matrix.json`,
   `validation-report.{json,md}`) are exempt from every tripwire here —
   their owning stage regenerates them on demand.
7. **Buildid drift gate (arbiter R8 — compliant, sanctioned by
   [§3.6](#36-required-retrofit-buildid-flag-on-both-cdb-tools))**: run_all
   passes defaults `BUILDID` on every invocation; with `--buildid <id>`
   given, every selected draft file's `_meta.buildId` must equal `<id>` —
   any mismatch ⇒ exit 1 naming the file, BEFORE any write (the same
   fail-loud doctrine rules 3–4 serve, strictly stronger than promoting
   first and failing at the verify gate). Without the flag the check is
   skipped — isolated-invocation convenience; the stage vectors
   ([§3.1](#31-pipeline-exact-commands-in-order-stop-on-first-nonzero),
   [§4.1](#41-pipeline-exact-commands)) always pass it.
8. Summary stdout: per-file action + totals; exit 0.

### 3.6 Required retrofit: buildid flag on both CDB tools

### 4.4 Dangling/unverifiable edge policy (frozen)

- **Dangling (`valid:false` — target id absent from a target sheet that HAS
  inline ids)**: count must be **0** at every gate; any positive count fails
  cdb_verify (exit 1) and therefore the stage. Policy: a dangling edge is an
  emitter/verifier disagreement or real authoring drift — it is never
  silently shipped, downgraded, or dropped; diagnose before rerun.
- **Unverifiable (`valid:null` — declared target sheet has no inline lines:
  hidden sub-sheets or the datafile-backed roots place/group/element/
  levelProps)**: allowed to ship, never counted as dangling, MUST stay
  enumerated — regeneration-honest population exactly **72**
  (env__place 61, frescos__place 9, fiefGoal__element 2). The ledger
  splits each entry into one of two states (arbiter F2):
  - *unknown* — no decoded evidence either way yet; unblock **R1
    (HBSON decode)**.
  - ***dig-adjudicated pending wiring*** — all 72 current entries: Dig 7's
    decoded-id-set adjudication resolved them `true` (`hbson_emit.py`;
    as-found `_meta` carries `"verifiedBy": "Dig D7 (hbson_emit.py)
    against the decoded HBON id set"`, `unverifiableBefore` 61 / 9 / 2,
    `allEdgesVerifiedTrue: true`). The machine flag stays
    regeneration-honest `null` until id registries enter the pipeline
    (wave 3, unblock R1); the RELATIONS.md ledger renders the adjudication
    text beside the flag instead of lumping these pairs with unknowns.
    Regeneration drops the D7 stamps every run by design (the
    [§2](#2-ground-truth-frozen-numbers-must-reconcile-exactly) freeze
    policy) — that is the knowledge-preservation debt, carried as the
    named wave-3 unblock, not a dataflow contradiction (arbiter B1).
  When registry wiring lands, its id registries turn `null` → `true|false`
  and the count re-freezes (EXTRACTION-LOG §5 procedure). The count is
  asserted per-pair by tests ([§7](#7-test-spec-for-testwriter) F3/I2), so
  silent growth or shrinkage of the ledger fails the build.

   (mandated AT that exact path by localization-architecture §5.4) would
   fail `_meta.edges` parsing. Required fix (part of E2's hash refresh):
   consider a reldir file a pair file iff its name matches
   `<kind>__<kind>.jsonl`; list-and-count anything else as skipped. The
   wave corpora in both draft dirs are unaffected; the non-pair
   `poi_coordinates.jsonl` sitting in `relinks/_draft/` since Dig 7 is
   caught by the same name rule — skipped and enumerated, never parsed
   (the live `KeyError: 'fromKind'` on today's own draft dir is the proof
   the rule is needed now).
2. **Hardcoded BUILD_ID in both tools** breaks the one-command patch rerun —
   retrofitted as [§3.6](#36-required-retrofit-buildid-flag-on-both-cdb-tools).
3. **`_meta.emitted` defeats byte-idempotency**: the emitter stamps wall-clock
   time, so reruns can never be byte-stable; the promote equality rule
   exempts exactly that field ([§3.4](#34-promotion-tool-promote_draftspy)
   rule 2) rather than weakening idempotency to "row counts equal".
   Declared exemption (arbiter F9/m1): run REPORTS
   (`validation-report.{json,md}`) keep their wall-clock `generated` on
   purpose — a report that cannot say when it ran is a worse defect than a
   git diff. Derived DATA artifacts (`matrix.json`, `RELATIONS.md`) get no
   stamp and are byte-stable across reruns
   ([§4.2](#42-catalog-generator-relink_catalogpy)).
4. **Full walk still gates on decompile**: flipping 4–6 to BUILT does NOT
   make a no-args run reach them — stage 3 fails loudly first (exit 3, its
   pointer). Isolation mode is the supported path until the decompiler
   lands; documented in E4, not worked around.
5. **Availability regenerator reads `_draft`, not canonical**: wave-1-only,
   by design of the locale-bridge dig; stage 6 keeps it unchanged because
   stage 4 always regenerates drafts before emit can run (precondition),
   and the generalization is queued (R9). Recorded so nobody mistakes the
   3-kind availability scope for the 40-kind dataset scope.
6. **Kind-vs-sheet naming trap**: `craft` emits as kind `recipe`;
   `class` as kind `class` from sheet `unitClass`; three sheets take
   synthetic ids (`frescos` on its unique `place` ref; `env`/`craft`
   zero-padded ordinals, `keyRule` in `_meta`). Every join key, matrix row,
   and filename uses KIND names; cardinality on synthetic-keyed kinds is
   computed on the synthetic id. Tests pin the mapping once (F2).
7. **`pipeline/tools/` is git-swallowed**: the root `.gitignore` `tools/`
   rule makes all three NEW tools local-only until negation lines land
   (EXTRACTION-LOG §2 footnote ¹ precedent) — hash-pin discipline continues;
   a fresh clone restores by hash. Recorded, not papered over.
