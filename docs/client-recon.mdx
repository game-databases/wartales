## 2. Pak format (fully decoded)

All four paks share one format. Header magic `50 41 4B 00` (`PAK\0`) — this is
the Shiro/Motion-Tune-lineage packer, **not** the standard Heaps `PASH`
container.

```
Header (16 bytes):
  u32 0x00  magic "PAK\0"
  u32 0x04  boundary = byte offset where directory tree ends / data begins
  u32 0x08  unknown, high-entropy, differs per pak (seed or checksum; unresolved)
Directory tree (depth-first pre-order, from 0x0C):
  node := u8 nameLen, name[nameLen], u8 flag
  flag 1 (dir):   u32 childCount, then childCount child nodes
  flag 0 (file):  u32 offset, u32 size, u32 crc-like hash   → data region 1
  flag 2 (file):  u32 A, u32 B, u32 size, u32 crc-like hash → data region 2
Tree trailer: u32 0x41544144 = ASCII "DATA", then payload regions begin.
```

Evidence, all read-only:

- **Boundary field verified exactly**: each tree walk ends at `boundary − 4`
  with the `"DATA"` marker there (all four paks). E.g. res.pak: boundary
  31,005; tree bytes [16..31,001); `"DATA"` at [31,001..31,005).
- **Two data regions, byte-perfect accounting**: for every pak,
  Σ(flag-0 sizes) + Σ(flag-2 sizes) == (fileSize − boundary), delta **0**:

  | Pak | Boundary | Files (flag0+flag2) | Region 1 Σ | Region 2 Σ | Data span | Δ |
  |---|---|---|---|---|---|---|
  | assets.pak | 730,870 | 17,131 (4,167+12,964) | 2,147,741,708 | 7,068,992,299 | 9,216,734,007 | 0 |
  | content.pak | 484,823 | 15,248 (4,530+10,718) | 2,147,793,663 | 5,218,579,279 | 7,366,372,942 | 0 |
  | map.pak | 229,523 | 6,886 (4,250+2,636) | 2,148,002,816 | 25,740,783,459 | 27,888,786,275 | 0 |
  | res.pak | 31,005 | 936 (936+0) | 767,068,478 | — | 767,068,478 | 0 |

  Totals: **40,201 packed files** in 2,084 directories. Region 1 sums sit just
  above 2 GiB in three paks — consistent with a packer that fills a first
  store to ~2³¹ and spills the rest into region 2.
- **Region 1 addressing verified by content**: flag-0 offsets tile [0,
  region1Σ) with zero overlap and zero gaps; probing computed positions returns
  correct magics (`DDS` at tile offsets, `PNG`, `HBSON` at prefab offsets).
- **Region 2 addressing verified as sequential**: entries stored back-to-back
  in tree order; reading at `region2Base + cumulative(sizes)` yields correct
  magics (8/8 `DDS` probes in map.pak; `HMD`/`DDS` probes in assets.pak).
  The flag-2 `A`,`B` u32 pair remains semantically unresolved (B ≈ IEEE float
  28.0 + small varying mantissa bits) — irrelevant when reading sequentially,
  relevant only if random access is ever required.
- **No encryption**: names plaintext, payload probed readable.
- **No compression observed**: contiguity holds and probed payloads are raw
  final formats (DDS/PNG/HMD/HBSON), not framed compressed streams.

Payload format notes (from magic probes):

- `.fbx` entries are **not FBX** — they carry the Heaps `HMD` model format.
- `.png` entries may carry **DDS** payloads (e.g. normal maps) — extension lies.
- `.prefab` and most `/content` blobs are **HBSON** (Heaps BSON serialization).
- `res.pak` carries the game's brain: `/data.cdb` (6,088,918 B), `/formulas.hx`
  (687 B), `/texts.xml` (159,673 B, **French dev-pivot source**), `/lang/*`
  (17 files), `/content/script/*.hx` (12 Haxe scripts incl. `World.hx`),
  `/content/systemic/names.yml`.

Per-pak role split (depth-1): assets.pak = `/assets` 10,190 + `/chars` 6,128 +
`/ui` 813 (incl. `style.css` 779,142 B + CJK/KO variants + `.asl` icon
styles); content.pak = `/prefabs` 15,248 only; map.pak = `/assets/worldmap`
6,886 (albedo/normal DDS tiles + region shape JSONs); res.pak = everything else.

## 8. Unexpected findings & open items

1. **Pending patch** (TargetBuildID 21238928, ~3.4 GiB queued) — snapshot/pin
   before extraction (§0).
2. **`res.pak` ≠ `res/`** naming trap: the pak holds data/lang/scripts, the
   folder holds Wwise audio.
3. Extensions lie systematically: `.fbx`=HMD models, `.png` sometimes DDS,
   prefabs are HBSON. Unpacker must route by magic, not extension.
4. Game logic ships as readable artifacts: `.hx` scripts (hscript) including
   `World.hx` and `formulas.hx`, plus `names.yml` — direct logic-layer input.
5. `export_*.xml` sheet names give the `data.cdb` schema without parsing CDB —
   schema bootstrap for the whole entity model.
6. No anti-cheat, no video, no workshop integration (only
   `steam_autocloud.vdf`); co-op runs over Steam (`steam_api64.dll`,
   `steam.hdll`) — protocol surface exists via Steam networking for co-op sync;
   single-player fully offline.
7. Two near-identical boot images (`hlboot`/`sdlboot`) — extract once, diff once.
8. Open question for unpacker authoring: semantics of flag-2 fields `A`,`B`
   (random-access addressing?) — sequential read already proven sufficient.
9. `mysql.hdll` presence is stock HashLink distribution, not evidence of a DB.
10. Locale headers carry `version`/`revision`/`date` — free per-locale
    provenance stamps for patch-diffing.
