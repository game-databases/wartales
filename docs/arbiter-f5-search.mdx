## 3. Adjudication — `## r1 conflicts` item 2 (binding)

Exact clauses to amend (both currently assert state that becomes false the
day F5 mounts):

1. **F4 §8 AC-11** — "`data-shell-slot="search"` present **and empty** in
   served header HTML … **no search input, no 'Search' nav word**". Two legs
   die post-F5: the slot holds the mounted field host, and the closed-state
   chrome word renders in served HTML.
2. **F4 §7.6 smoke check-list line** — "absence of `/en/` internal hrefs and
   of **any search control**; `data-shell-slot="search"` **empty** and
   `data-search-swap-root` present …".

Amendment (one clause each, keeping the check green in both eras): the slot
leg becomes "**present; empty until F5 mounts, then containing exactly the
F5 search-field host and nothing else**"; the control/word-absence legs
become "**shell code itself renders no search input or search word beyond
F5's mounted host**" (or equivalently scope them "pre-F5"). The swap-root
leg and the `/search`-absence legs stay untouched — they survive F5
unchanged.

Why (a) and not (b) transient sequencing: `smoke.mjs` is not a one-shot
acceptance snapshot — it is a standing executable runner F4 ships as a
script (`npm run smoke`), and this pack's discipline is suites that keep
guarding after later pieces land (F4 keeps `tokens.test.ts` byte-guarding
forever; F5's own route-absence test is explicitly designed to keep guarding
post-F4/PT16 with ABSENT-line reporting). Left unamended, F5's landing turns
a permanent guard permanently red — noise that masks real regressions — and
AC-11 becomes unverifiable-green ever again, i.e. unfalsifiable as an
exactness claim. Timing makes the amendment pure spec text today: F4 has not
built (`site/scripts/`, `app/**` absent on disk), so the orchestrator routes
the wording change into F4's spec before its builder writes `smoke.mjs`;
zero code-level conditionals needed. F5's side needs no change — H-3 and the
conflicts item recorded the edge honestly, and F5 correctly cannot touch
F4-owned files.

Conflict item 3 needs no ruling: it defers to F4's recorded `pt-br`
decision with a one-row flip law, which matches F4 §2/§9 as verified.

## 4. New defects found in the sweep

- **N-1 (MAJOR — verdict-driving). §9 suite 1's ko jamo case is frozen to a
  false expectation; AC-9 red as written.** Suite 1 asserts "`한국` ↔
  `ㅎㅏㄴㄱㅜㄱ` **equivalence**"; §4.3 justifies it with "both sides normalize
  identically". Executed in Node with the exact §4.3 pipeline:
  `normalize("한국")` = `U+1112 U+1161 U+11AB U+1100 U+116E U+11A8` (syllables
  decompose with **jongseong** finals), while `normalize("ㅎㅏㄴㄱㅜㄱ")` =
  `U+1112 U+1161 U+1102 U+1100 U+116E U+1100` — compatibility jamo
  (`U+3131/U+3134`) fold to **choseong** forms (`U+1100/U+1102`), never to
  jongseong. Full-string equivalence is **false**; a table-driven TestWriter
  writes a guaranteed-red case or silently rewrites the expectation — the
  same defect class the r1 revision existed to close, in a case it re-froze
  without executing (M3's execution covered pl only). The property the spec
  actually needs survives: `normalize("한국").startsWith(normalize("ㅎㅏ"))` is
  **true**, so AC-8's "ko jamo partial" leg is unaffected. Fix is two lines:
  re-freeze suite 1 to the true assertions (`normalize("한국") ===
  "한국"`, the startsWith prefix law, and

  §4.3's ko bullet from "normalize identically" to "normalize to conjoining
  jamo, so partially-typed jamo prefix-matches".
