## Adjudication — `## r1 conflicts`: F2-vs-F4 pt-BR segment collision

**Ruling: (a) — a genuine cross-spec contradiction that must be surfaced to
the orchestrator as errata.** Not merely a segment-vs-BCP-47 naming
distinction: BCP-47 never enters URLs on either plane (F2 §4, F4 §2 agree),
and the hreflang/lang layer PT16 §3.2 already disambiguates correctly. The
collision lives one layer deeper — **page-path segment vs client code
across the page→data boundary** — and two frozen clauses cannot both be
applied literally to the same production URL:

- F4 §2 freezes the page segment id `` `pt-br` `` (recorded r1 decision,
  lowercase-hygiene rationale, "Orchestrator may override before first
  deploy; flipping this §2 row is the whole change").
- F2 §4 asserts, of page URLs, "**Locale segments** = the 8 non-pivot
  CLIENT codes, exact strings: `de es fr ko pl pt-BR ru zh`", and F2 §6
  freezes the derivation over them: *"take the page path, strip the
  optional leading locale segment, prepend `data/`, append `.json`"* —
  with F2 §15 AC7 implementing the strip against
  `api.manifest.json.locales.prefixed` (client codes).

Composed literally on an F4-conformant page, `/pt-br/item/Gold` strips to
`pt-br` — outside F2's declared locale set — and yields
`/data/pt-br/item/Gold.json`, while F2's own plane pins
`/data/pt-BR/item/Gold.json`. This is invisible to both specs' own gates:
F2 AC7 probes only `sorted(prefixed)[0]` = `de`, so its bijection passes
green without ever exercising Portuguese-Brazil. Exactly one of the two
frozen clauses must change; both candidate errata are one-clause edits:

1. **Primary (recommended): exercise the override F4 §2 itself reserves —
   flip the `pt-br` row's `id` cell to `pt-BR` in
   `docs/spec-f4-app-shell.mdx` §2**, updating the derived mentions as
   consequences (§3 `defineRouting` array, §4 message filename
   `pt-br.json`, §7.2 expectation, §8 AC 2 probe, §2 recorded-decision
   paragraph). Page segments then equal client codes for all eight
   prefixed locales; F2 §6 composes verbatim with no bridge; PT16 §9(4)'s
   published rule becomes true as written; and the URL spelling
   re-aligns with [DR-2026-08-20-locale-urls] ¶2's own `/pt-BR/…`
   illustration. Cost: F4's recorded lowercase-hygiene preference.
2. **Alternative (keeps lowercase): amend `docs/spec-f2-contracts.mdx`
   §6's derivation rule** to insert the bridge step — strip the optional
   leading locale segment, **normalize it to the client code through the
   pack's single locale bridge** (`src/i18n/locales.ts` /
   `api.manifest.json` `locales`), prepend `data/`, append `.json` — with
   the same normalization inside the manifest's `derivationRule` string
   and one `pt-br`-spelled page case added to F2 §15 AC7's probe set. F4
   untouched. Cost: F2's "bijective, mechanical" rule gains one
   normalization step forever.

**What PT16 must do either way (binding downstream):** the fixer's core
claim holds — emitted links survive both arbitrations *because* they are
derived from the manifest and the loaded records, not by string surgery on
page paths. Keep it that way. Until the errata lands, §6.4's "derived from
the page path by F2's frozen derivation rule" and §9(4)'s "stated
verbatim" must be emitted as the **manifest-mediated rule** (enumerate
`locales`, construct `/data/{clientCode}/{kind}/{id}.json` from the
record), never as the unconditioned page-path formula — otherwise llms.txt
publishes a derivation that 404s every pt-BR entity JSON under errata
option 2, violating seo-standard §9's stable-data-URL actionability rule
and the machine plane's own precision doctrine ([DR-2026-08-18]). No PT16
edit is directed now; this ruling fixes the implementation posture and the
llms.txt wording slot.
