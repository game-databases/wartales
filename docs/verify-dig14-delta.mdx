### D-1 — MINOR: 6 keyed fr rows the emitter cannot see (`<t id ="…">`)

Master `texts.xml` contains six `<t>` rows whose attribute has a space
before `=` — `<t id ="noRecipe">` etc., all under
`ui/brewBarrel/noValidBarrel/`. Standard XML reads them fine (my expat
walker keys all 6); the emitter's `_TAGOPEN` attribute scan requires the
quote immediately after the name, so they land in parseProblems as
"<t> without id/_id" (6 lines, unquantified) and are dropped:

```
master texts.xml <t … id ="…"> rows: 6 -> ['alreadyDone','noBonus','noLevel','noRecipe','noResources','noUnitAssigned']
keys my parser reads but the shipped fr table lacks: 6 ['ui/brewBarrel/noValidBarrel/alreadyDone', …]
disclosed only as unquantified parseProblems lines: 6 e.g. 'ui/brewBarrel/noValidBarrel: <t> without id/_id @79332'
other 8 locales' files carry spaced-id rows: 0 everywhere
```

Consequences: the true addressable fr namespace is **1,903** (1,897
shipped + 6), full-namespace en−fr is 251 = **245 truly id-less + 6
skipped-with-id**, and the docs sentence "all 251 correspond one-for-one
to id-less `<t>` rows in the fr master" (Dig 14 log entry +
[locale-key-convention §8.3](locale-key-convention.mdx#8-dig-14-extension-all-cdb-text-kinds-ui-namespace-r5-stamps)
+ [PROOF.md](../extracted/PROOF.md) R9) is correct only for 245/251.
Impact: 6 site-chrome strings, fr only, one nested brew-barrel group;
the depth ≤ 1 claim (111) is unaffected (the 6 sit at depth 3).
Suggested one-liner fixes: widen the attr regex to `([\w.\-]+)\s*=` (or
quantify these 6 in the inventory) and reword the sentence to "245
id-less + 6 with a space-broken `id` attribute".
