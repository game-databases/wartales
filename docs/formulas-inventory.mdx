# Wartales formulas inventory — hscript + CDB logic layer

Every formula the game computes that is **visible in this dig's sources**:
`res.pak:/formulas.hx` (687 B), the 11 `res.pak:/content/script/*.hx`
hscript sources, and the formula/script columns of `res.pak:/data.cdb`
(386-sheet census: [cdb-census.mdx](cdb-census.mdx)). Client buildid
**20318128**. Machine-readable twin:
[`extracted/logic/formulas.jsonl`](../extracted/logic/formulas.jsonl)
(23 rows, emitted by `pipeline/tools/formula_emit.py`, every number read
live from `data.cdb`). Parameter registry companion:
[`extracted/logic/constants.jsonl`](../extracted/logic/constants.jsonl)
(all 1,266 `constant` rows with difficulty variants resolved).

Status vocabulary (per row):

- **[CLIENT]** confirmed-in-client — value(s) read directly from client
  files in this dig.
- **[MIXED]** parameters client-read, the composition that combines them
  still lives in `hlboot.dat` bytecode.
- **[COMM]** community-inferred — hand-measured or argued by players, no
  client read yet ([tools-plan §2](../tools-plan.md#2-mechanics-enumeration)
  status legend).
- **[P0-DIG-HLB]** remaining dig target: the 16 MB HashLink bytecode.

**Bytecode cross-reference:** the hlboot types-walk outputs landed while
this dig ran ([`extracted/logic/hl-structure/`](../extracted/logic/hl-structure/):
types/functions/globals/strings/natives registries). Every formula row was
probed against the 75,321-string pool of `hlboot.dat` — results in §5:
all parameter sets are **double-confirmed** (their identifiers appear in
bytecode), while the three `formulas.hx` pricing functions appear nowhere
in bytecode — they are **hscript-only**, evaluated by an embedded
interpreter at runtime. Per-row annotations live on each
[`formulas.jsonl`](../extracted/logic/formulas.jsonl) row's `bytecode`
field.

## 1. Verbatim hscript formulas (`formulas.hx`)

The file holds exactly four functions. Three are pricing formulas; one is
a CDB data validator. All verbatim, byte-identical sources at
[`extracted/logic/hscript/formulas.hx`](../extracted/logic/hscript/formulas.hx).

### 1.1 `weaponPrice(v: Item)` — [CLIENT]

```
price = 10 + v.tier * 10
if rarity == 1: price += 20     # Uncommon
if rarity == 2: price += 30     # Rare
# rarity == 3 (Legendary): NO surcharge in this function
```

| param | source | notes |
|---|---|---|
| `v.tier` | item tier int | linear +10/tier |
| `v.rarity` | item sheet enum `C,U,R,Legendary` | flat +20/+30; Legendary falls through |

Tool use: base weapon price before town/region/perk modifiers.
Cross-ref: [tools-plan §2 row 1](../tools-plan.md).

### 1.2 `itemPrice(i: Item)` — [CLIENT]

```
if i.price != null: return i.price        # explicit per-item override (1,743 of 2,125 items)
walk i.type → parentType chain:
    first itemType whose props.basePrice != null wins
else return null                         # comment: "will create NaN"
```

Findings from the sheets it reads: `item.price` populated on 1,743/2,125
rows; `itemType.props.basePrice` is **datafile-backed** in this build
(0 inline of 96 types) — its values ride the HBSON prefab payload, so the
fallback path resolves only after HBSON decode (dig-log queue item 3).

### 1.3 `craftPrice(c: Craft)` — [CLIENT]

```
p = Σ itemPrice(ingredient.item) * ingredient.qty   over c.recipe
return p / itemPrice(c.item) - 1                    # cost-margin ratio
```

0 = break-even, negative = craft sells under material cost. The hidden
float column `craft.calcPrice` exists on the sheet but is populated on
**0/667 rows** — an editor-side helper; the value recomputes at runtime.

### 1.4 `validatefiefEvent(e: FiefEvent)` — [CLIENT], not a game formula

CastleDB authoring validator (`Warning("Null") / Ok / Error("Not Done")`
on `e.done`). Recorded for completeness; zero tool value.

### 1.5 Region scripts and `World.hx` — state, not math

The 9 region-named `.hx` files plus `World.hx` are **global-state flag
registries** (167 World flags + 644 region flags = 811 flags/counters:
quest stages, arena completions, all
five path progressions Crime/Might/Trade/Knowledge/Mystery-step flags,
fief tutorial). `Paths.hx` is an empty stub (`function onInit_Paths(){}`).
No numeric formulas live there — but the flag vocabulary IS the
quest-state schema guides and completion trackers will join against
(tools-plan rows 12/14/16). Preserved verbatim under
[`extracted/logic/hscript/content/script/`](../extracted/logic/hscript/content/script/).

## 2. Runtime skill-script layer (`skill.script`, 1,130 bodies)

`data.cdb` sheet `skill` column `script` (`text kind=script` — the census
[type table](cdb-census.mdx#column-type-system-every-type-encountered-payload-verified))
carries hscript evaluated by the engine at runtime. This is a real
logic-layer corpus, not flavor text.

### 2.1 Damage surface — [CLIENT] fields, [MIXED] composition

| input | where | coverage |
|---|---|---|
| `minDmg` / `maxDmg` | skill top-level floats | 394 skills |
| `dmgAttribute` | `skill.props` enum index into `attribute` | 389 skills → Strength 244 · Dexterity 105 · Constitution 40 |
| `apCost` | `skill.props` | 159 skills |
| `vars.valueN` | `skill.props.vars` / per-level `levels[].props.vars` | 852 skills |
| script hooks | `onEval/onSkillEval` (pre-resolution), `onHit`, `onDamage/onDamageDealt`, `onBeginAction/onEndTurn`, `onSkillPlayed`, `onPostSkill` | see below |

Hook census across the 1,130 bodies: onSkill 368 · onDamage 285 ·
onEval 182 · onHit 159 · onSkillEval 121 · onDamageDealt 114 ·
onBeginAction 113 · onStatus 37 · onDeath 35 · onMove 8.

Runtime API exercised by the scripts (engine-implemented, so its final
math is bytecode-side): `damages()`, `getPercentHealth()`,
`gainsHealth()`, `pushback()`, `opportunityAttack()`, `attackTarget()`,
`addStatus()/hasStatus()/cancelStatus()`, `corrupt()/canCorrupt()`,
`getFoes()/getAllies()/getMeleeUnits()`, `getDistance()`,
`criticalHitDamageBonus`, `damageHealth`, `movePoints`.

Representative verbatim bodies (full corpus:
`output/_dig-formulas/skill-script-bodies.txt`, local-only scratch):

- Crit modifier (DaggerSpe5Skill1): `s.criticalHitDamageBonus += vars.value1; if (s.isPatience()) s.damageHealth = true;`
- Percent-health nuke (TitanicRoar): `a.target.damages(skill, a.target.getPercentHealth(vars.value2), true); a.target.pushback(...)` — desc interpolates the same `::value1::/::value2::`.
- Animal regen aura (BeastMaster): `u.gainsHealth(ceil(u.stats.health*vars.value1/100))` gated on `skill.level == 2`.
- Knockout-kind guard (KnifeThrow): `if (s.kind == Skill.KnockOut) return;` — confirms KnockOut as a first-class skill kind on the capture path.
- Ghost curse hook (Corrupt): `canCorrupt(u)` gate in `onEval`, `corrupt()` application in `onSkill`.

Tool use: damage-estimate engine inputs for the flagship build planner;
armor/guard/crit final resolution stays
[P0-DIG-HLB] ([tools-plan §2 row 15](../tools-plan.md)).
