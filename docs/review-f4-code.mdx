## B. Deviation adjudication

**(a) Next 16 middleware dispatch rewrite — JUSTIFIED.** Spec §3 said
"wraps createMiddleware with one pre-shim"; the build keeps
`createMiddleware(routing)` (middleware.ts:32) as the dispatcher for the
eight prefixed live locales (:100) and takes over the pivot hop (:111–117)
and the serving gate (:82–105). Every DR law the rewrite exists to protect
was verified live (§A above): 301-permanent external `/en*`, no negotiation,
unknown-segment 404, core-owned 308. Nothing diluted. Forward-risk note
recorded as N4.

**(b) Served-404 documents composed at the serving layer — JUSTIFIED, and
its premise is independently verified true.** The claim was that on Next 16
a buffered `notFound()` cannot emit localized chrome/`<html lang>` in the
server HTML. Verified: a request that bypasses the middleware matcher and
reaches `[...rest]` → `notFound()` (e.g. `/de/not-a-route.txt`) returns the
framework error shell — `<!DOCTYPE html><html id="__next_error__">` with no
lang attribute and no chrome in server HTML — while the middleware-composed
document (`middleware.ts:131–153`) delivers everything AC 14 asserts:
true 404, `<html lang="de">`, chrome copy from the same nine message files
(no second vocabulary), landmarks, plus `noindex` meta + `x-robots-tag`.
Both mechanism files remain in place ([...rest]/page.tsx:12–21,
not-found.tsx:9–19). Residue noted as N5.

**(c) Pivot switch link as plain anchor + sr-only anchor row — JUSTIFIED.**
The claim "an explicit `locale` prop would force-prefix it" is true in
next-intl 4.13.7:
`node_modules/next-intl/dist/esm/development/navigation/shared/createSharedNavigationFns.js:41`
sets `forcePrefix: locale != null` ("Always include a prefix when changing
locales"), which flows into `applyPathnamePrefix` (utils.js:140–160) — so
`<Link locale="en" href="/">` would emit `/en`, violating §3 rule 2. The
plain anchor to `/` (locale-combobox.tsx:53–59) keeps the pivot bare. The
sr-only row (:83–98) restores the crawlable cross-locale link graph because
Radix portals never SSR popover content — without it AC 5's served-page
switch links would not exist; the smoke leg passes ×9.

**(d) ui/utils.ts beyond §9's letter — JUSTIFIED.** `cn` is required by all
three shadcn copies; the alias is registered where shadcn expects it
(`components.json` → `"utils": "@/components/ui/utils"`). One-file shape
matches shadcn convention; no second vocabulary introduced.

**(e) THE CROSS-PAIR TOUCH — edit to sibling-owned scripts/smoke.mjs
pivot-301 leg — JUSTIFIED.** Verified against actual response semantics:
this machine's conformant app answers `/en` with the raw relative header
`location: /`. The old line
(`(res.headers.get("location") ?? "").replace(/\/$/,"")`, smoke.mjs:305 at
600b0e6) maps that to `""`, while the leg compares against
`wantLoc("/en") === "/"` (smoke.mjs:300) — so the root leg was unpassable
for ANY app that answers the required root location (absolute forms ending
in `/` strip just as fatally). The replacement (smoke.mjs:305–309) strips a
trailing slash only when `raw.length > 1`, preserving `/` while still
normalizing `/de/` → `/de`; status-301 and exact unprefixed-Location
assertions are unchanged, so no spec assertion was weakened — an unpassable
assertion became a passing one that still fails any nonconformant app. The
diff is 5 lines including its justification comment, in a file the spec §9
itself assigns to this piece (the TestWriter landed it first, blind, at
600b0e6 — an orchestration artifact, not a build defect).

**(f) Tooling artifacts — JUSTIFIED.** `site/AGENTS.md` / `site/CLAUDE.md`
are generated by `next dev` (Next 16 writes the agent block itself; the
file states committing it keeps the tree clean) — deleting them only
re-creates the dirty tree, and gitignoring them would contradict §9's own
pinned two-line `.gitignore` extension. The tsconfig test exclusion is
ruled a MINOR dilution instead (N2).

## D. Correctness / security sweep

Live probes against a scratch dev server (Next 16.3.3):

- **Open-redirect surface of the 301 shim**: `/en//evil.com` → core
  normalizes first (`308 → /en/evil.com` → `301 /evil.com`, same-origin);
  `/en/https://evil.com` collapses to a single-slash PATH and terminates in
  a 404, never an off-origin Location; backslash forms normalize the same
  way; `%0d%0a` stays percent-encoded inside the Location value (no header
  injection); `..%2f` → 404. No open redirect found.

- **SSG claims**: build output proves nine SSG homes; `generateStaticParams`
  returns the nine ids (`layout.tsx:13–15`) and `setRequestLocale` is called

- **Error boundaries**: no `error.tsx` — runtime errors get the framework
  default 500. Spec §9 never lists one; recorded, not counted.
